## 4. 低代码与插件化分工

Agent专项以[57号](57-Agent运行框架最新源码研究.md)与[58号](58-Agent技术架构与性能实施设计.md)为当前细化：优先一个可运行后端，复用现有运行合同适配DSH/pi/Codex候选，按同样本验证再替换。默认不采用多后端动态路由或运行器套运行器；减少模型调用和复用确定性业务服务也是低代码的一部分。插件树、RPC、SDK都不能替代原权限、业务幂等及正式交付事务。

| 能力 | 优先复用/配置 | 最小定制点 | 插件边界 |
|---|---|---|---|
| OA流程和职责 | 原生流程设计器、候选人规则、审批、会签 | WorkItem与版本交付适配 | 配置包只引用既有节点类型 |
| 业务表单 | 原生表单设计器、字段校验、布局和条件显示 | 输出合同与事实基线映射 | FormVersion+字段Schema；不嵌任意JS/SQL |
| 页面 | 原生路由/权限菜单、表格、表单、抽屉、图表 | P02左对话右工作区、鱼骨路径和版本视图 | 受控组件注册，默认复用成熟组件 |
| 数字员工/技能 | 原生Agent与提示词版本、已有执行图 | 本人任务Binding/快照/责任轮次守卫 | 配置扩展；不创建第二Agent循环 |
| 工具/连接器/模型 | 原生OpenAPI、MCP、模型Provider适配 | 动作合同、独立执行Grant和输出发布 | 工具声明是能力描述，不能自行授予权限 |
| 知识/本体/分析 | 原生摄取、检索、指标查询、图表 | 来源版本继承、关系断言、受众投影 | 用已有检索或只读查询SPI；不叠加新知识平台 |
| 主动任务/进化 | 原生调度器和资源版本发布 | 去重、冷却、评测指纹、试用回退 | 版本化配置；无自改核心权限入口 |

默认仅“选择用途→推荐配置→预览并应用”三步。高级参数跟随具体任务按需展开；管理员看到影响范围和依赖，普通员工看到业务解释。低代码设计器不把授权、并发控制、幂等或事务一致性下放到浏览器。

**判断是否写代码**：先查底座现成能力→能配置就配置→能用扩展点就写小适配→仍无法实现不变量时才新增领域服务。每个新增表/服务/包须记录“现有机制为何不能满足”及对应验收。34张候选表是完整物理参考，不是要求创建34张表；[存储复用计划](../../contracts/storage-reuse-plan.json)要求逐表映射，优先复用原表和版本能力。

## 5. 插件生命周期与依赖

```mermaid
flowchart LR
  D[草稿配置或插件版本] --> V[Schema/依赖/权限请求/许可证检查]
  V --> T[隔离测试与固定样例]
  T --> R[有权维护者评审]
  R --> E[启用精确版本]
  E --> S[新任务快照引用该版本]
  E --> X[停用并检查依赖]
  X --> B[回到兼容旧版本或人工模式]
```

默认构建时模块注册与配置发布，不引入动态加载不可信代码。运行中任务固定版本，升级只影响新任务；紧急撤权优先于版本固定。停用普通插件时先停止新引用，已有任务由有权人员按依赖影响接管；权限/外部效果未知时不得降级为绕过检查。卸载不能删除审计、版本文件或历史交付。

插件清单见[plugin-manifest.schema.json](../../contracts/plugin-manifest.schema.json)，示例只含虚构声明且`enabled=false`，未安装、未授权、未实测。清单不能保存真实凭据、任意脚本、全局管理员或通配外发许可。

## 6. 变更、冲突与接续

本包细化27/40的拟议合同；发现冲突按“原需求→领域语义→精确机器合同→底座映射”处理，不能由代码生成工具自行选择。旧40号示例中的`WAITING_REVIEW`不是Attempt合法状态；本包保持`WAITING_HUMAN`，审核属于WorkItem/Review。46以后使用`baselineRef`等VersionedRef统一版本字段，兼容旧示例只在唯一adapter转换，服务端拒绝含糊的双字段。

修改需求先更新权威需求；修改API先更新合同和负例；修改持久字段先更新数据字典、迁移影响和恢复步骤；修改插件能力需重验调用者、输出和历史任务兼容。所有完成声明分为文档检查、参考样例、实际产品、生产四层。

## 7. 最新标准的使用范围

本包有意选用OpenAPI 3.1.1与JSON Schema 2020-12作为合同格式，不宣称3.1.1是最新版本；选择理由是可表达封闭对象与按命令区分的请求。规范说明见[OpenAPI官方规范](https://spec.openapis.org/oas/v3.1.1.html)和[JSON Schema官方版本](https://json-schema.org/draft/2020-12)。MCP用于工具接入方式，输入/输出Schema与不可信工具注解的边界见[MCP官方工具规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)。这些来源支持协议设计，不证明本项目适配器已实现。
