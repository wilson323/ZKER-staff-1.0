## 4. AI编程与产品AI必须分别验证

**研发AI**是Codex等编码者。它需要当前任务范围、权威资料、实际仓库目录、允许动作、可运行检查和接续证据。现有AGENTS、项目Skill、开发体系、REVIEW和currentTask已具备方法骨架，不再新建一份“万能AI开发规范”。已有[研发Agent评测](../../validation/development-agent-evals.json)继续使用原编号；其模型行为回放尚未执行，不能被工具回归替代。

**产品AI**是员工任务中的数字员工。它需要ExecutionGrant、任务快照、受控工具、输出发布、用量及真实业务评测。用研发Agent能修改文件证明产品数字员工安全，或用产品聊天成功证明研发流程有效，都是错误归因。

RAG需测引用支持、无答案与撤权；分析需测指标口径、空值/零值和同源下钻；主动能力需测去重、暂停与过期；进化需测候选/基线对照、独立复核、试用和回退。它们可按阶段增加同一产品评测集，不必每项搭一套Harness。质量阈值由样本与业务风险确定，本轮不编造通过率。

## 5. 首个M1切片的规格应该细到什么程度

目标沿28号：**登录→同人两笔业务→本人领取与配置→输入快照→真实产物→人员确认提交→刷新/重启回读**，保留不依赖模型的人工完成路径。先满足这条链路，不同时铺开22页。

| 必须回答的问题 | 开发合同应给出的内容 |
|---|---|
| 开发到哪里 | 选定底座的实际模块与前端组件；本次需求ID/AC/EW、允许文件与排除项；不能只写全产品目录名 |
| 用什么数据 | 两名人员、两笔业务、不同范围资料的合成夹具；固定来源版本与预期可见字段；测试身份不含真实凭据 |
| 怎样开始一次执行 | C06所需字段/条件/错误；当前责任与资源授权；幂等请求如何与旧operation匹配；一个意图只形成一个有效执行 |
| 同键重复与新请求如何区分 | 同键同正文返回原操作的当前获准投影；同键异正文冲突；查询结果仍鉴权。明确检查顺序，不能因重试错建Attempt或泄露旧正文 |
| 执行中改派或撤权会怎样 | 旧epoch/fence/Grant不能进行新动作或发布；在途无法收回的效果进入真实记录；新承担人重新确认；UI清理旧投影 |
| 暂停/停止/断网如何恢复 | 可控制阶段、确认回执、检查点、UNKNOWN工具效果和有限恢复；浏览器重连只观察，不再次开始 |
| AI完成怎样成为业务完成 | 候选产物、人员决定、CompletionCheck和DeliveryCommit分层；旧审批/旧来源失效；数据库与流程事务/恢复动作明确 |
| 怎么证明不是模拟成功 | 真实API、数据库/文件回读、引擎状态、当前浏览器和故障注入的独立断言；记录运行来源，未执行项保持NOT_RUN |

这些规则中的业务方向已存在于27/34/39—41，本节指出必须补到可执行程度的地方。并发中的具体隔离级别、租约参数、重试界限和错误优先级由切片规格与实测冻结，不让不同Agent分别猜默认值。

## 6. 分阶段补齐，避免文档先膨胀

1. **现在**：统一入口与文档优先级，保留原需求和未决事项；本轮已完成这部分审查与导航修复。
2. **M0实验准备**：选择一个候选的实验范围，补D02/D06中可复现输入、动作和判据；复用36固定来源与43的八类POC。实验使用候选不等于最终选型，失败可淘汰。
3. **M0通过、M1开工前**：冻结当前切片所需的D01—D08合同、样本和检查。形成实际决策后，才同步37—42及技术映射。不要要求先把全部173项写成最终DDL/API，也不要用“先编码再补合同”推迟安全关键决定。
4. **每个后续切片**：按需求ID补精确合同/实现/测试引用，代码变更与合同一起审查。未纳入范围的需求继续保留，不能因试点结束被删掉。
5. **发布前**：补齐实际容量、负责人、依赖交付清单、版本升级、恢复演练与可访问性证据；42号候选SLO不能直接充当承诺。

文档修改的同步规则：需求变化更新26/27/30对应位置；命令变化同步40和机器合同/消费者；数据变化同步39和迁移；权限变化同步34/41和夹具；底座变化同步37/38/42；验收变化同步28/当前任务与真实检查。上述是本项目适配建议，不是所有项目必须复制的目录规范。
