# 接口、事件与插件合同

开发文档包0.1｜`DESIGN_CONTRACT / NO_ENDPOINT_IMPLEMENTED`。承接27/40。完整动作列表、请求字段及Schema见[命令参考](../../contracts/command-reference.md)，机器合同见[OpenAPI](../../contracts/openapi.json)。此处冻结的是可评审设计格式；底座会话、外层响应、具体资源映射须M0验证后定版。

## 1. 协议、身份与统一边界

浏览器同源HTTPS调用`/oa-api/v1`。示例cookie名`OA_SESSION`仅用于表达会话安全方案，M0必须映射底座原有会话，不能新增身份系统。所有写入验证CSRF和Origin。来自浏览器的tenantId/actorId均被封闭请求Schema拒绝；resource ID、member ID仍须服务端核实对象关系。

前端只保留一个API adapter：解开底座外层封装后得到本包业务DTO。401不是空结果，HTTP200也不是业务成功；Operation.status必须确定。动作域的字段不存在时拒绝，不允许把任意JSON、Java方法名、SQL或系统提示词放进通用commands分发器。

WorkspaceView显式携带当前subjectId/tenantId/purpose、过期时间、请求代次和获准nodes/edges；主体字段只由服务端返回，不接受客户端身份注入。C01_getWork要求X-Request-Generation并回显，用于防止旧UI回包覆盖，不作为授权依据。只返回端点均已获准发现的边；边数和缺口不泄漏隐藏结构。

| 类别 | 精确约定 |
|---|---|
| ID | 服务端不透明ID，1—64字符；人员/租户从受信会话解析 |
| revision/epoch | 正安全整数，1—9007199254740991；空/负数/小数拒绝 |
| 时间 | API为带时区RFC3339；内部UTC；展示按人员时区；调度保留IANA时区 |
| 金额/精确小数 | JSON十进制字符串；货币单独大写三位代码；服务端核允许币种 |
| VersionedRef | kind/id/version/digest全有；版本不可变；kind与命令目标类型再校验 |
| null与省略 | 只有Schema明确允许null时可为null；可选字段省略表示未提供，不表示删除 |
| 列表 | 默认20，最大100；游标不透明，绑定主体/租户/筛选/策略/快照；数据本身先鉴权 |
| 大小 | 普通正文建议256KiB，消息文本10000字符；资源数组100个；文件上限首期50MiB |
| 未知字段 | 请求拒绝；生产升级先发布兼容客户端/服务端，再切换合同版本 |

VersionedRef中的digest不是权限凭据；不得把不同kind但相同id视为同对象。API字段名与39号数据库snake_case间只允许显式映射。

低代码表单字段值还要按已发布FormVersion验证：fieldKey不得重复，key和type必须匹配该版本白名单，必需字段和跨字段业务约束在服务端执行。通用FieldValue通过只证明值结构合法，不允许用户或模型绕过具体表单规则；未知字段、重复字段、错误类型和不可见/不可写字段均拒绝。

## 2. 动作、并发和幂等

C01—C31按`command`常量区分动作。一个HTTP路由使用`oneOf`，每个动作有独立封闭对象。动作共用状态、权限与预算守卫；不能通过换路由绕过原对象命令。C27采用配置建议最终调用C04或同一个原对象更新服务。

写请求携带`Idempotency-Key`。键作用域为tenant + 原始actor + 精确command + key，规范化摘要包含方法、规范路径及正文；同键同摘要返回原operation，异摘要409。前端刷新或网络重试沿用键，用户明确新意图才新建。服务端并发插入用唯一约束，不能先查后插。首期保留至少7日，UNKNOWN记录在查证关闭前不可删除；保留期不是“到期后可以重复外部写”的许可。

所有修改现有对象的请求比较expectedRevision。责任相关命令再比较responsibilityEpoch；不混用If-Match/412。创建命令没有尚不存在的targetRef，用源版本/明确范围及幂等键。提交事务内做当前权限和源版本比较，不能只在网关或预检时检查。

C15.appendWorkMessage与saveMessageDraft补齐任务对话写入/草稿；发送消息不隐含开始Attempt或交付。公开给其他参与者前仍检查发布范围。C27.applyProposal/undo同时带目标提案expectedRevision与原配置baseRevision，单项outputFormat映射C04真实字段；agentVersionRef映射resourceRefs中的AGENT项，executionMode映射mode，禁止直接透传字段名。

工作路径及携带workId的责任命令中expectedRevision指WorkItem.revision；C07指Attempt.revision；其余有targetRef的命令指目标资源当前revision。C04返回Binding自身revision及workRevision，调用者不能混用。HumanTask的原生引擎版本由服务端同时核对。C16首次确认允许baselineRef=null，但只能在该工作尚无基线时CAS创建v1；之后必须给精确旧基线，null不能覆盖已有事实。C17.import创建新资源时使用artifactRef+targetScopeRef，不要求预先存在targetRef。

| 操作状态 | HTTP与客户端行为 |
|---|---|
| 读取成功、配置保存、上下文预览、预检、上传票据 | 200，按具体DTO读取 |
| 长事务或异步任务受理 | 202；保存operationId，展示受理状态，后续查询 |
| 同步确定的正式结果 | 以接口声明的200或查询Operation的CONFIRMED为准；202本身不证明完成 |
| PENDING_COMMIT | 已保存候选/交付意图，OA推进尚未确认；不启用下游 |
| UNKNOWN / RESULT_UNKNOWN | 显示查证入口；只查证原副作用，不重新提交 |

## 3. 错误及恢复合同

Error固定包含`code/message/requestId/retryable/recoveryAction/fieldErrors`。message是获准公开的业务描述，不能含源路径、敏感标题、凭据、工具参数或堆栈。

| HTTP | code示例 | 保留与恢复 | 服务端禁止 |
|---|---|---|---|
| 400 | INVALID_REQUEST | 定位字段，保留本地合法草稿 | 吞错误返回成功空对象 |
| 401 | UNAUTHENTICATED | 重新登录后重新取任务与权限 | 把登录页HTML当业务JSON |
| 403/404 | FORBIDDEN/NOT_FOUND | 无发现权统一404；有发现权可返回限定说明 | 泄漏他人任务名、数量、资料位置 |
| 409 | REVISION_CONFLICT/EPOCH_STALE/SOURCE_STALE | 回读版本，展示获准差异，重新核对 | 静默覆盖新配置或提交旧候选 |
| 409 | IDEMPOTENCY_CONFLICT | 显示意图冲突并停止；由用户明确新意图 | 自动更换幂等键重发写入 |
| 422 | MISSING_INPUT/REVIEW_REQUIRED | 定位有权补充/审核入口 | 通过默认空附件或假批准继续 |
| 429 | RATE_LIMITED | 显示重试时间/预算原因，允许人工接管 | 换模型/插件规避同一限额 |
| 503 | DEPENDENCY_UNAVAILABLE | 真实不可用态；只读可有限重试 | 无权限/无模型时伪造业务结果 |

UNKNOWN是事实不确定状态，不由通用retryable=true触发自动重发。写命令超时后客户端先查询operation；无operationId时按原幂等键在同请求接口查回原记录，不能新建意图。

## 4. 事件与SSE

[events.schema.json](../../contracts/events.schema.json)区分内部事件和PublicEvent。内部事件持有tenant、聚合、版本、关联/因果ID和受限记录引用；人员SSE采用单独允许列表，只有工作ID、序列、投影/权限代次、公开阶段及“重取获准快照”动作。默认不流式发送后台原始token、工具参数和私有推理文本。

`GET /work-items/{workId}/events`是观察接口。`Last-Event-ID`绑定主体/工作/策略；每次派发重验当前权限，非永久会话授权。事件ID去重，单聚合sequence拒绝倒退；缺口或游标超窗发reset，重新C01获取快照。保持一个订阅，不因切换文档或鱼骨图重复订阅。跨实例切换关闭旧订阅，并改变前端请求代次。

撤权事件触发清理内存、已渲染受限正文、查询缓存、预览Blob URL和对应草稿访问。旧HTTP响应即使晚到也须比较work/authz/projection代次后丢弃。撤权前已被合法人员下载的离线副本无法由浏览器强制追回；产品不能承诺追回，发布前须按目的控制。不会把内部事件的整体计数映射为人端隐藏分支数量。

Outbox与业务事务同提交；消费者inbox与本地应用结果同提交。外部OA/工具推进仍按业务幂等键查证，不宣称端到端“恰好一次”。详情见49/50。

集成Webhook不使用浏览器cookie/CSRF授权。注册来源用X-Integration-Key-Id定位秘密引用，对timestamp、nonce、方法、路径和原始正文摘要签名；服务端验证签名、建议5分钟时间窗、nonce重放及事件/对象/成员映射。同来源eventId异载荷拒绝。具体签名算法随已选底座现有集成机制固定，不能仅检查这些头存在就接受事件。

## 5. 上传、下载与异步读取

上传票据绑定主体/租户/工作/轮次/大小/MIME/期限。PUT原始字节进入隔离区；同票据同字节可重试，异字节409。上传完成后服务端重新读取实际对象、算摘要并检查解析/扫描结果；不信任客户端digest。未通过扫描不能成为可交付引用。

版本下载入口`/artifacts/{artifactId}/versions/{version}/content`重验当前读/下载动作；Range、缩略图、转换缓存、历史版同样保护。HTML/Office预览使用无同源能力沙箱；URL来源摄取先校验协议/地址/重定向，禁止访问内部元数据和未授权网络。提供者现有公开下载路由须一起关闭旁路。

异步领域操作以Operation返回状态和获准结果引用。领域结果经统一的版本资源读取接口返回类型化视图；不得让前端跟随私有storageRef。大正文/分析结果以ArtifactVersion承载，引用与图表明细同一结果版本。资源详情的底座原生接口由唯一adapter映射，未支持的动作明确不可用，不能伪造通用资源卡已能完成全页业务。

## 6. 插件的最小合同

插件结构见[Schema](../../contracts/plugin-manifest.schema.json)及[示例](../../contracts/fixtures/plugin-manifest.json)。普通员工只见“用途、来源、可用状态、所需连接、采用”；维护者才配置Schema和动作映射。

| 字段 | 作用与守卫 |
|---|---|
| pluginId/version/apiVersion | 稳定标识、精确版本、平台合同版本；不接受latest作为运行锁定版本 |
| kind | CONFIG_BUNDLE / BUILTIN_MODULE / OPENAPI_TOOL / MCP_TOOL；默认配置包和构建时模块 |
| entrypointId | 由已审查的底座注册表解析；不让清单指定任意shell/下载脚本 |
| actions | 名称、输入/输出Schema、风险、超时、幂等能力、权限请求与出站目标 |
| dependencies | 精确pluginId/version/digest；依赖图必须无环且版本合格 |
| configurationSchemaRef | 配置表单来自白名单Schema；秘密只在底座secret store引用 |
| provenance/evaluationRefs | 来源commit、license声明与隔离测试证据；声明不等于审核通过 |
| enabled | 示例false；只有实际通过安装/动作/任务检查后才可启用 |

平台可列出的插件动作集合 = 已安装合格版本 ∩ 当前授权动作 ∩ 本任务用途/目的地/预算。工具的readOnly或风险注解均是候选信息，宿主需要独立判断；符合[MCP工具Schema](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)也不等于已授权。

新增插件复用原连接器注册/资源发布/审计机制。首次接入只读试验、失效授权、超时、限额、同键重复、恶意返回值各一用例。不得创建绕过C24的插件权限页，或允许插件自调用C31发布自身。

## 7. 合同验证与兼容发布

本包独立脚本检查本次用到的Schema子集、每个动作的正常/缺字段/越界字段样本、局部引用、表字段关系和原需求映射；不冒充完整OpenAPI认证器。进入产品实现后使用所选语言的成熟OpenAPI/JSON Schema工具生成类型并验证全部规范语义，前后端契约测试必须访问实际HTTP。

破坏兼容的字段删除/类型改变/枚举改义使用新API或资源合同版本；只增加可选字段仍先测试旧客户端。后台快照和历史成果保留原schemaVersion，升级器显式转换并留来源摘要。插件停用/升级不改变已发布历史结果；安全撤权仍立刻生效。
