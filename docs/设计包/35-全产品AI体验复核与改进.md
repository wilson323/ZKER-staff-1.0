## 1. 主要判断与采纳边界

**全产品 AI 的下一步应是把用户的目标、已有设置、资料、结果与下一合法动作连起来。** 每页增加一个聊天框、把全部参数塞进“高级设置”、把人工确认改成绿色按钮，都不足以降低实际学习成本。需要减少的是重复输入、技术名词、无效选择和找不到恢复人的情况；需要保留的是责任、版本、授权用途和真实结果。

QoderWake值得借鉴的是从职责和可用资源开始、用小任务验证，再扩展自动工作。StaffDeck值得借鉴的是任务内可编辑草案、可打开的知识引用，以及带证据和差异的改进提案。这些机制与OA的人员任务结合后，员工可以直接完成业务，不必先学习如何搭建智能体。[QoderWake Waker管理](https://docs.qoder.cn/qoderwake/manage-wakers)、[StaffDeck草案组件](/Users/mac/Documents/StaffDeck-main/frontend-enterprise/src/pages/chat/components/ScheduledDraftCard.tsx:91)

本次复核中最明确的限制是：StaffDeck本地`evaluate`生成的评估模式仍为`static_v1`，检查结构、非空文本和是否有差异；`approve`再次调用同一评估，随后进入资源变更分支。它能支撑“可审阅的结构校验”，**不能证明基线/候选业务对照、质量提升或自主进化效果**。本项目不能照搬其状态名称并赋予更强的业务含义。[评估与批准实现](/Users/mac/Documents/StaffDeck-main/backend/app/evolution/service.py:98)

左侧对话、右侧鱼骨路径/文档/文件夹/历史摘要是当前已确定的任务工作台布局。商务、研发、采购均只是例子；下面的决定适用于不同人员、对象、动作、用途和有效期。后台被授予输入使用权，不代表当前人员可读取原文、分析明细、引用标题、历史摘要或未经批准的结果。[当前权限决定](/Users/mac/Documents/OA数字员工协作平台/docs/设计包/34-任务执行工作台与权限分层设计.md)

## 2. 六个领域的简化决定

以下均为本项目的**设计推导与实施建议**，不是对竞品全部功能的陈述，也不是已实现承诺。

| 领域 | 普通员工首先看到 | 系统应替用户完成 | 仅在必要时由有权人处理 |
|---|---|---|---|
| 设置 | 当前任务的目标、依据、交付、待决定事项 | 继承合格资源；预填已知业务条件；指出真实缺项 | 更换能力组合、连接授权、公共模板和运行边界 |
| 分析 | 一个业务问题、当前统计范围、可复核的答案 | 匹配已发布口径；执行授权只读查询；生成图表和明细关联 | 影响结论的歧义、未定义指标、数据质量或权限问题 |
| 知识 | 问资料、看依据、看相关对象 | 提取和关联已有对象；索引授权资料；标记冲突及过期 | 来源映射、关键关系核对、正式口径发布 |
| 主动 AI | 当前待办旁一条有依据、能处理的建议 | 合并同类事件；去重、冷却；在已有授权内准备草稿 | 新的自动执行范围、需人员决定的动作、异常恢复 |
| 自主进化 | 结果旁反馈、员工详情中的改进建议 | 关联反馈与具体版本；准备差异；按已授权规则评估 | 业务效果判断、试用范围、共享发布和回退 |
| 全局体验 | 当前事项与本人下一步；同一工作台 | 跨页保留合法对象定位；按职责组织入口；保留草稿 | 对象歧义、资料撤权、转办、来源改变和正式交付 |

### 2.1 设置：从已有方案开始，按影响程度决定交互

任务内“协助设置”打开当前工作台的设置面板。默认展示“本次将帮你做什么、基于哪些已获准资料、准备什么成果、何处需要你处理”。已有信息直接呈现，不重新问实例、负责人和截止时间；用户可用一句话修改本次目标。模型、协议、并发、分块、提示词文件和参数Schema留在对应维护页面，不在每次任务开始时再次选择。

采用三种不同交互，避免把所有设置都变成审批：

| 变化 | 交互与文案 | 保存及恢复 |
|---|---|---|
| 当前用户明确提出的个人显示/通知偏好，且允许、可逆 | “已应用到我的设置 · 撤销” | 记录旧值；撤销前检查是否已有后续修改，不覆盖较新设置 |
| 本次任务配置、资料选择、成果格式 | 显示可改单项的差异；主操作“采用本次方案” | 默认仅本任务；版本冲突保留本人草稿并重新比较；保存后另有“开始准备” |
| 涉及他人、共享模板、权限或对外动作 | 提案显示确切对象、内容版本、范围与处理人 | 按既有授权和业务命令办理；已经有效的授权不重复要求确认 |

推荐资源时同时显示“可用”“需要本人连接”“当前任务不允许”等真实资格。一个资源被复制或启用，并不能据此显示为可运行。缺连接时给到精确来源及有权处理人；能人工继续的业务保留人工路径，不能让员工为连接故障重建一个数字员工。市场采用后回到原任务并保留未完成配置，不能把人留在资源目录。

状态闭环：`已有配置 → 生成/编辑建议 → 校验差异 → 已保存 → 启动时重新校验 → 运行/待处理`；模型不可用回到普通表单；差异过期回到比较；运行失败保留配置和阶段产物。文案分别使用“已保存”“可开始”“已生成候选”“待审核”，不用一个“成功”覆盖所有阶段。

验收重点：给一个信息完整、资源合格的任务，首次准备不要求填写技术字段；修改一项并采用后，未选项不变；切到另一个实例不会带入上一个实例的私有资料；保存但未启动时没有执行回执。反例是“AI已配置完成”后实际缺账号、按钮只跳页且丢失输入，或一次个人修改影响全部员工。

来源依据：QoderWake强调预置职责、必要资源与小任务验证；StaffDeck草案组件在`95—108`行检查名称、执行内容和计划，`124—127`行把编辑后的草案交给确认回调，`162—165`行支持取消编辑。这是静态交互依据，未运行创建接口；其基本非空检查不能代替本项目的权限、版本、计划有效性与幂等检查。[Waker管理](https://docs.qoder.cn/qoderwake/manage-wakers)、[ScheduledDraftCard.tsx](/Users/mac/Documents/StaffDeck-main/frontend-enterprise/src/pages/chat/components/ScheduledDraftCard.tsx:95)

### 2.2 分析：先用组织口径回答，只有实质歧义才追问

分析入口保留“问业务数据”。输入下方用一行说明当前可分析的业务范围和数据时间；默认使用已发布的指标口径。问“本周哪些任务逾期”时，若组织已经定义“本周”和“逾期”，直接查询并把口径随结果展示；若“任务”在当前场景可能指人员任务或业务实例且计数不同，先给一个业务选择。不要让每个问题都经过粒度、SQL、图表类型、模型、数据集五层向导。

结果依次展示：结论、支持它的表/图、统计范围与时间、来源/口径、下一步。高级展开可以查看查询计划和执行标识；普通员工通过“查看这些事项”复核。日期、时区、去重、状态过滤、分子分母与空值处理由同一口径版本控制，图表和明细不能各自计算。

状态闭环：`输入问题 → 范围/口径匹配 → 必要澄清 → 查询中 → 有依据结果`。权限变化、过期快照或修改口径后，旧结果标明已过期并重查，不继续作为可采用结论。失败保留问题和已明确条件，给重试、缩小范围或转交数据负责人的入口。

| 状态 | 用户应看到 | 禁止的错误表现 |
|---|---|---|
| 有统计样本，目标事件为零 | 显示0及完整统计范围 | 把没有逾期的样本写成没有数据 |
| 无样本或比率分母为零 | “当前范围无可统计样本”；比率显示“—”并解释 | 默认生成0%和趋势改善结论 |
| 无权/权限刚被撤销 | 允许披露的不可访问说明及恢复入口 | 用0、空图或“另有若干隐藏对象”代替授权结果 |
| 查询失败/超时 | 失败阶段和可行恢复动作 | 用模型猜测或前次结果伪装新查询完成 |
| 有结果但依据过期/冲突 | 标明限制并提供更新时间或口径负责人 | 隐去限制，只展示流畅结论 |

结果中的“准备处理清单”生成待审阅草稿，仍绑定原事项和当前版本；不直接批量改负责人、形成个人绩效评价或发送消息。后台服务能读更广数据时，不能把其总数、占比、交叉筛选结果或小样本切片直接展示给人员；聚合输出也要按当前接收者和用途控制，防止通过反复筛选推断受限事实。

验收重点：用固定测试集验证人员任务/实例去重、边界日期、零样本和失败；核对图表、表格、下钻的数值一致。相同问题由权限不同的两人提出，分别验证查询与返回字段，不只检查图是否隐藏。报表分享与导出重新判定接收范围，不能继承生成者的读权。

来源依据：Fabric官方文档描述自然语言生成、校验和执行查询，并使用请求者的凭据、权限和只读连接。这支持把技术复杂度放在受控查询服务内，不能据此保证任意问题正确、无需治理或任意模型自带同样的安全能力。[Fabric data agent concepts](https://learn.microsoft.com/en-us/fabric/data-science/concept-data-agent)

### 2.3 本体知识：用问题和依据进入，用关系解释，不让员工先建图

“业务知识”默认提供问题输入与当前任务的相关资料。答案里的引用在右侧文档区打开到具体版本和位置；“相关对象与关系”是解释和浏览入口，知识维护者才进入映射与待核对队列。员工不需要先填写实体类型、关系类型、嵌入参数或绘制图谱才能获得资料答案。

对象来自已接入的业务主记录；用稳定ID关联人员、任务、业务对象、资料、运行与交付。别名和同名歧义可以形成候选，但合并主记录、改变负责人或修订正式口径必须回源系统的合法命令。知识图不是第二套可写业务主表。“本体能力”首期应体现在更准确的关联、来源和影响解释，技术实现由最终底座决定。

把两条链分清：

| 链路 | 状态与责任 |
|---|---|
| 来源可用 | 已接入/上传 → 加工中 → 加工失败或可检索 → 生效/过期/撤权；维护者处理来源问题 |
| 派生关系可信与可分享 | 候选 → 待核对 → 已核对/已拒绝 → 按接收范围发布 → 来源变化后待重核；有权事实或口径负责人处理 |

“已核对”只表示某人核对了该条断言；不隐含源记录已改、所有人可读、当前所有任务都采用新版。低风险关系可由已有批准的规则批量验证，高影响或冲突项再交给人，避免每份文档产生几百条无意义人工确认。系统需保留采用规则、证据和可纠正入口。

来源冲突时并列展示冲突主张、各自来源版本与适用范围；无权读取其中一份时仅显示获准的冲突处理状态，不暴露标题、内容或隐藏数量。历史摘要沿节点、轮次、来源和发布版本定位，不能把几轮讨论压成一个无版本“最新事实”。不能把检索相似度显示为事实准确概率。

验收重点：同名两个对象不能自动合并；引用能打开正确版本；源文档撤权后搜索片段、关系邻居、文件名、计数、历史摘要和原直链均重新判定；来源更新后，相关候选标记待重核，已经正式交付的旧版本仍可按获准审计范围追溯。

来源依据：QoderWake区分原资料与编译知识、上传与可检索，并要求用已知、边界和未知问题验证；StaffDeck知识页面提供候选确认/拒绝，引用组件提供打开动作；PROV-O从实体、活动和主体开始描述来源，可渐进扩展。本项目采用其机制，不照搬所有对象、状态和设置项。[QoderWake知识库](https://docs.qoder.cn/qoderwake/knowledge-base)、[知识候选操作](/Users/mac/Documents/StaffDeck-main/frontend-enterprise/src/pages/KnowledgePage.tsx:1896)、[引用打开](/Users/mac/Documents/StaffDeck-main/frontend-enterprise/src/pages/chat/components/KnowledgeCitationList.tsx:23)、[PROV-O Starting Point](https://www.w3.org/TR/prov-o/#description-starting-point-terms)

### 2.4 主动 AI：把提醒和执行分开，先解决一个真实缺口

默认入口在已有待办内，不要求所有人维护自动化控制台。建议卡只解释“为什么现在出现、影响哪件事、可以准备什么、谁需要决定”。点击“准备草稿”进入同一任务工作台；点击“稍后”或“忽略本次”只影响建议，不改变OA任务。相同业务变化经多个渠道到达时，收敛为同一建议或同一授权执行，不让每个渠道再发一次。

员工确有重复工作需要时，以自然语言生成计划草案：“每个工作日上午检查我的待办，把资料缺项整理成草稿”。确认页显示可理解的触发、下一次时间及业务时区、对象范围、预期产物、授权边界和期限。技术Cron、Webhook和游标参数属于维护细节。重复日期、是否补跑错过周期等会改变业务结果的条件仍要明确。

三套对象各有状态，但复用已有数据与执行链：

| 对象 | 状态闭环 | 用户控制 |
|---|---|---|
| 单次建议 | 待处理 → 已采用/稍后/忽略/事实失效 | 解释原因、准备草稿、稍后、忽略本次 |
| 自动计划 | 草案 → 校验/试运行 → 启用 → 暂停/到期/停用 | 修改范围、暂停新触发、继续计划；已有合法授权不重复询问 |
| 一次执行 | 排队/运行 → 等待人员/候选/失败/部分完成/取消 | 查看进度、停止当前执行、查证回执、转人工 |

“暂停提醒”不等于停计划；“暂停新触发”不等于停止当前运行；“停止当前执行”先呈现取消请求，收到确定结果再显示已停止。若外部动作结果未知，先查原操作和产物，不能把“重新运行”作为唯一恢复按钮。人员离岗、任务结束、范围授权到期后停止相关机会与新触发，责任落到当前人员任务，不能由旧账号继续默认执行。

验收重点：回放同一事件两次只产生一个有效工作；忽略后没有新事实不再提醒；暂停计划后当前执行仍按真实状态显示；取消途中保留已发生动作；模型或连接不可用时不无限重试。普通员工不必填写去重键、预算计算规则或恢复脚本。

来源依据：QoderWake官方区分自动触发、运行过程和实际产物，并要求先验证任务及依赖；微软人机交互指南要求情境适时、易忽略、易纠正。本项目据此增加建议、计划、执行的可理解分界。[QoderWake自主工作](https://docs.qoder.cn/qoderwake/automated-tasks)、[微软人机交互指南](https://www.microsoft.com/en-us/research/articles/guidelines-for-human-ai-interaction-eighteen-best-practices-for-human-centered-ai-design/)

### 2.5 自主进化：自动准备证据与候选，人只处理有依据的改变

日常入口放在结果旁的“这里不对/这种方式合适”，不强迫填写评估表。可选说明是哪项事实、格式或方法需要改变，并自动关联本次运行、资料和产物版本。反馈只表示其实际含义：“本次采用”不自动成为“所有任务都要这样”，“忽略提醒”不自动成为“建议内容错误”。

个人明确要求的低风险表达偏好，可在既有范围内生效并可撤销；改技能、工作方法、检索规则或共享模板则形成提案。不能把每条错字纠正升级成组织发布流程，也不能把改变职责、权限或审批的请求归入普通学习自动生效。可学习对象的范围不能包含安全、授权和OA正式责任规则。

提案卡默认只显示：发现的问题及真实例子、改变了什么、影响哪些使用点、当前证据阶段、下一步是谁。展开后看到基线、候选、案例、模型与工具版本、评分规则、失败案例及回退点。没有业务评估记录时直接写“尚未评估业务效果”；“结构检查通过”保持为一个单独阶段。

### 2.6 全局体验：同一工作对象，随任务变换展示，保留确定入口
