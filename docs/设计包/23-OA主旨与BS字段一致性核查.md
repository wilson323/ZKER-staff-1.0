# OA 主旨、B/S 形态与字段一致性核查

日期：2026-09-11。对应原型：v2.6。

## 1. 本次用户确认的统一产品基线

**本项目是企业 B/S 软件：在 OA 工作流程中增加数字员工。流程把人、责任和任务连接起来，承担人在自己被指派的任务内，按权限选择并配置自己的数字员工，由数字员工协助完成工作。**

主线是：业务申请 → 具体流程实例 → 人员待办 → 本人配置数字员工 → 执行、检查与本人确认 → 审批或交接 → 下一位承担人。

人有多个待办，一个流程模板有多笔业务实例，一个实例可以有并行节点，一个人也可能承担同实例的多个节点。数字员工定义可以被多项工作使用；每个节点/工作项的当前分配、上下文快照、运行Attempt、草稿和交付分别隔离。人对责任和授权承担义务，数字员工运行完成不自动等于业务交付完成。

QoderWake用于节点内数字员工配置与协作体验参考。OA统一待办、审批、流程实例和人员责任决定本产品的信息架构。AI个人助理、独立对话、临时工作、数字团队等既有能力继续保留，通过既有入口及对象关系融入平台。

## 2. B/S 一致性规则

| 项目 | 统一口径 |
|---|---|
| 用户入口 | 企业浏览器访问；宽屏和窄屏是响应式布局，不是桌面安装包 |
| 身份与租户 | 服务端Cookie会话及当前成员关系；演示角色切换器不进入真实产品 |
| 流程与业务状态 | 服务端持久化；浏览器展示授权投影，不能凭界面按钮设置权威完成状态 |
| 数字员工运行 | 现有服务端Runtime Gateway/DSH；浏览器发起受控请求、显示进度和结果 |
| 文件和知识 | 上传、企业连接器、对象存储及获授权引用；服务器不能凭用户本机路径读取文件 |
| 凭据 | 员工界面使用连接名称、状态和授权范围；敏感值保留在服务端受控机制 |
| 本机能力 | 已有受控设备桥接能力保留为条件能力，使用具体设备/资源授权；不改变B/S主入口 |
| 断线与恢复 | 按业务实例、任务和事件水位恢复；不能因刷新浏览器重复发起业务或重复外部动作 |
| 当前HTML | 仅为本地打开的交互设计样本。页面内存不代表生产存储，角色夹具不代表真实认证 |

这些规则与当前[产品需求](<01-产品需求与业务规则.md>)及[正式架构决策](</Users/mac/Documents/ChatGPT/ZKER- staff/docs/ai/decision-register.yaml>)共同约束后续开发。开源引擎与成熟前端仍是[选型候选](<22-开源工作流与成熟前端复用选型.md>)，本次没有安装或替换。

## 3. 已发现并修正的具体不一致

| 编号 | v2.5问题 | v2.6修正及准确含义 |

| C01 | 采购、合同、报销、人事共用项目与金额 | 拆为4类模板字段；人事交接不含金额/币种；金额分别叫申请预算、含税合同金额、申报报销金额 |
| C02 | 输入框未表现不同模板必填、金额和日期规则 | 发起页随模板切换；正金额、两位小数、合法日历日期、模板内字段集合检查；不接受跨模板塞入金额 |
| C03 | 所有任务都把第二阶段标为当前处理阶段 | 新申请属于登记阶段、审核属于复核阶段、已结束实例不标活动阶段、抄送不标本人执行阶段；其他阶段不虚构已完成 |
| C04 | 审核演示任务没有来源提交版本也能决定 | 没有目标提交版本时禁用决定动作并说明原因；正式提交产生的独立审核保留通过/退回交互 |
| C05 | 逾期示例截止时间早于该业务实例发起时间 | 改为09:45截止、10:00观察，仍演示逾期且时间先后合理 |
| C06 | “今天需要关注”下计入跨日期待办；列表只展示时分 | 标为当前待办概览；发起信息包含月日和时分；业务时区明确 |
| C07 | “我发起的”误用处理期限筛选而产生空结果 | 实例分类禁用不适用的任务期限筛选；其他任务分类继续支持期限过滤 |
| C08 | 脱敏视角的抄送复选框可访问名称仍含真实样例单号 | 可访问名称与可见编号应用同一假名投影 |
| C09 | 无数字员工的人工任务配置却标为人机协助 | 无助手配置使用空引用和人工执行，不虚构数字员工使用状态 |
| C10 | 修改授权申请范围/有效期后，审批页仍固定显示项目A和7天 | 审批页读取本次申请的实际范围和天数；保存决定说明；天数按本演示允许的整数范围验证 |
| C11 | 自动化时间和时区保存后回显默认值 | 回显实际保存的时间和时区；同一工作活动尝试限制与多工作并行分别说明 |
| C12 | 职责页发起流程只设置布尔值，没有进入统一实例列表 | 复用OA创建函数，生成同一实例模型及待办；“我发起的”能找到该笔申请；输入变更需重新检查 |
| C13 | 流程管理页将“方案节点已提交”放在实例状态字段 | 改为方案节点状态，不暗示整个流程结束 |
| C14 | OA业务定位和B/S边界主要写在文档，首页表达不够明确 | 首页加入OA人员主线、本人配置数字员工、浏览器/服务端分工和演示标识 |

“人工任务”和“数字员工配置”可以共存：本人可以选择人工执行，或在人机协助模式下选择符合本任务要求的数字员工。示例角色没有市场权限时只展示已获准动作；这不代表该岗位永远不能取得市场使用权。正式页面仍须按实际授予、对象关系和任务责任投影，不能把演示角色表硬编码成永久业务政策。

## 4. 字段来源必须分层，不能统称已准确

| 层次 | 范围 | 本次证据 | 能证明与不能证明 |
|---|---|---|---|
| 存量合同字段 | [11号字段字典](<11-存量合同字段字典.md>)的64个JSON Schema、895条字段 | 对64个源文件逐一重算SHA-256，全部与导出快照一致，未增删源文件 | 证明字典来源未漂移；不能证明895条都已接线到界面或数据库 |
| OA新增读模型 | [20号InboxEntry候选Schema](<20-OA统一待办候选.schema.json>) | 继承已有正反例结构验证 | 仍是合同候选，不称为现成生产接口 |
| 企业业务表单 | [24号模板字段候选](<24-业务模板字段候选.json>)的4类、17项字段定义 | 原型字段隔离、金额/日期、必填和提交结果专项检查 | 是合理且标明来源的虚构样例；不是客户最终采购、合同、报销、人事表单 |
| 角色界面字段 | 全41视角可进入页面、节点标签及OA任务详情 | 浏览器采集字段名称、内容、控件类型、必填和禁用状态 | 字段清单用于后续逐项追踪；没有把清点数量冒充全部语义已验收 |

因此，回答“字段是否全部准确”：**已经修正可证实的错误，并核对存量合同字典来源；完整生产字段绑定与客户业务表单仍未验收。** 不能由布局通过、按钮可点击或截图数量推导全部字段准确。

17项业务字段的规则及限制：

- 采购：采购项目、申请预算金额、币种。
- 合同：关联合同事项、合同相对方、合同类型、含税合同金额、币种；当前只演示服务/采购合同，不覆盖无金额协议的全部变体。
- 报销：报销人员、费用类型、费用发生日期、申报报销金额、币种；费用日期不得晚于示例业务日期。
- 人事：交接人员、原任职岗位、接收岗位、交接生效日期。

本示例金额限人民币正数与两位小数；生产金额应采用固定精度或最小货币单位。人员/岗位示例是显示文本，真实B/S系统应从获授权目录选择并提交稳定ID。证明材料、发票明细、合同条款、审批路由等更多企业表单字段继续由模板设计定义，不能由这17项推断已完整覆盖所有业务。

## 7. 存量功能保留的开发验收约束

**现有代码中已经具备的功能是后续开发的最低基线。** OA主线整理、菜单调整、QoderWake体验参考及开源框架引入均不得导致能力减少。153项设计需求是已有追踪集合，不是代码功能数量上限；在当前代码中发现未被该集合描述的能力，也必须纳入保留映射。

每项受影响能力须记录“当前代码/路由与命令 → 使用角色与对象范围 → 新页面入口 → 字段、状态和异常路径 → 对应回归证据”。现有测试随实现保留，必要时调整适配；不得通过删用例、隐藏菜单或改为静态占位来宣称功能已保留。

| 验收对象 | 必须保留的行为 | 后续开发所需证据 |
|---|---|---|
| 功能入口 | 既有页面、独立会话、临时工作及管理能力仍可由获授权用户到达 | 当前路由与新入口逐项对应、真实浏览器操作 |
| 人员与权限 | 员工和管理员功能边界、成员关系、租户隔离、资产及操作权限 | 同角色同对象的允许与拒绝场景 |
| 业务命令 | 发起、执行、暂停/恢复、确认、审批、交接及已有异常恢复语义 | 原有消费者测试、API与服务端状态核对 |
| 资产与配置 | 数字员工、市场、技能、工具/连接器、知识、记忆、团队、自动化、渠道及条件设备能力 | 原配置兼容读取及有效执行，版本/授权/依赖信息可追踪 |
| 数据与产物 | 既有工作历史、上下文、附件、结果、审计和引用关系可访问 | 升级前后业务关联及可见范围核对 |
