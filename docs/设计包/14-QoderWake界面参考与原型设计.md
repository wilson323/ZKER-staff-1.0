# QoderWake 界面参考与原型设计

日期：2026-09-11｜原型版本：v2.3｜范围：现有交互原型及 UI 设计说明  
用户要求：原型结合 QoderWake 的前端 UI 设计。采用本机正在运行的 QoderWake CN 页面作为视觉与交互参考。

当前原型已扩展到 v2.4；角色设计与当前验证见 [15-全角色界面与操作覆盖矩阵.md](<15-全角色界面与操作覆盖矩阵.md>)。本文保留 v2.3 的竞品参考和验证快照，下文五视角及204/57不代表当前覆盖。

本机 `http://127.0.0.1:19830/` 返回 HTTP 200，监听程序为 qoderwake。实际浏览了任务看板、Waker 管理、Waker 详情、能力与资源中的技能/连接器市场、@Waker、自主工作，并读取 DOM 及关键计算样式；资源页另以 390×844 查看移动布局。版本号未从页面确认，因此只以本次采集时间标记现场版本。

[采集记录](<validation/qoderwake-reference/capture.json>) 保存实际地址、屏宽和截图路径。参考截图保留本地；持久化桌面截图裁去账号与项目侧栏，管理/看板只截取通用头部。竞品中的其他项目名称、岗位配置、任务状态没有作为 ZKER-staff 的业务事实，也没有导入本项目原型。

来源交互限制：管理按钮第一次鼠标点击被卡片统计层遮挡，随后通过已观察按钮的 DOM 点击打开详情；连接器标签改以其实际副标题定位后进入。这里只确认页面形态，不据此宣称竞品所有鼠标路径无问题。没有提交编辑、授权、安装或运行命令。

移动观察：QoderWake 在 390px 宽现场仍保留约 240px 固定侧栏，主内容被截到屏幕边缘；本原型使用可展开导航和单列资源卡来适配窄屏，因此没有照搬这一限制。

## 2. 原型的视觉规则

| 元素 | QoderWake 当前观测 | 本轮原型采用 |
|---|---|---|
| 桌面侧栏 | 宽 240px，背景 rgb(249,249,249) | 240px，#F9F9F9；1050px 以下收至 210px；700px 以下为移动导航 |
| 主内容 | 白底、28px/600 标题、细灰分隔 | #FFFFFF；标题 28px/600；主区左右 40px，窄屏 16px |
| 主次动作 | 黑色主按钮，白色边框次按钮 | 黑底白字主按钮；4px 圆角次按钮；禁用状态保留解释 |
| 工作记录 | 浅绿底容器、独立白色统计卡 | #EAF7E7 的记录区；绿色用于进展和少量强调 |
| 导航与标签 | 浅灰选中导航；黑色底线标签 | 相同层级；当前页面使用 aria-current；市场标签使用 aria-selected |
| 卡片和控件 | #E6E6E6 边框；4–8px 圆角；紧凑正文 | 数字员工卡 7px、资源卡 6px；桌面市场三列，1024px 两列，390px 一列 |
| 字体 | DM Sans 与系统字体栈 | 使用本机系统和中文字体；未下载 DM Sans，字形与原站会有细微差异 |
| 图标与头像 | 线性图标、角色头像 | 本地内联线性 SVG 与职责标记；不复制竞品人物素材或商标 |

这是本设计包的界面方案调整。正式产品仍需要将上述规则映射到现有组件和 Token，不修改生产主题、UI 库或权限系统。

默认打开任务看板；`?view=node` 可直接打开原节点工作区。

| 页面 | 本轮已可操作的演示 | 现有设计映射 |
|---|---|---|

| 节点工作区 | 五种角色的配置、上下文、贡献、审核与提交；原状态机完整保留 | P02/P03/P04/P16/P20 |
| 任务对话 | 输入补充要求、文本安全呈现、本地演示回复、当前职责/依据/接收人、进入上下文或交付检查 | P11/P20 |
| 我的数字员工 | 个人资源卡、市场副本、职责/技能/工具/知识摘要、进入本次配置 | P05/P09 |
| 能力与资源 | 顶部三类资源、市场标签、分类与授权数量、搜索、详情、复制到本人资源并用于本人节点 | P06/P07/P22 |
| 管理入口 | 流程设计者显示 SOP Studio；资源维护者显示资源与版本管理 | P13/P19；原型显式权限夹具 |

对话使用本地固定演示反馈，不调用模型或工具。新输入按角色分开保存于内存，切换页面保留，重置或刷新清除；不把这些数据当作正式工作记录。对话本身不会完成审核或提交节点。

## 4. 保留本项目的产品关系

QoderWake 的资源和执行视角适合承载每位员工的节点工作。本项目在这套界面基础上持续展示：业务流程位置、本人职责、各人的数字员工、共同事实版本、专业贡献状态、下一接收人以及交付检查。

主执行人和协作人分别配置自己的数字员工。协作人提交贡献，主执行人接受贡献，审核人独立作出决定，主执行人提交节点；这些动作仍然独立。资料更新时旧预算保持可追溯，但须重核后才能作为当前合格贡献。

员工侧有市场。查看、复制和使用分别授权，已有合法权限与依赖齐备即可直接选用。复制保留来源与版本，不继承作者凭据、私人记忆和业务文件。正式应用使用服务端可见集合与 allowedActions；演示工具栏的角色切换不是产品授权入口。

## 5. 开发交接

本轮没有新增需求编号或页面域。153 项需求、21 个领域、22 个页面组及人员/上下文/市场合同保持原范围；本轮补足 P01、P05、P11 的演示，并统一 P02/P22 的呈现。

开发时复用现有 React/TypeScript 组件、路由及状态管理。看板统计读取本人工作聚合；任务对话绑定 WorkItem/ConversationSession；数字员工目录读取个人与授权共享资源；市场使用已有类型授权和采用链。禁止将原型的角色数组、内存复制函数、固定对话反馈搬成生产 Provider。

## 6. v2.3历史验证结果与边界

本轮三个浏览器脚本均退出 0：

- 节点回归：54 组屏宽/角色/标签布局检查、8 项交互。
- 市场回归：75 组屏宽/角色/标签布局检查、19 项交互。
- 工作台与新页面：75 组屏宽/角色/页面布局检查、30 项交互。

合计 204 组布局检查、57 项交互、21 张原型截图；页面脚本错误为 0。布局检查验证横向溢出、页面内容和对应视图，不等于完整可访问性认证。另人工查看当前桌面看板/市场/对话/数字员工和手机看板/市场/对话共 7 张截图。

市场第一轮有 15 个空副本页面被旧脚本的“文字必须超过 30 字”条件误判；实际无溢出，空状态标题和说明完整。验证器改为检查标题、说明存在和布局边界后重跑通过，保留初次结果便于复核。未靠补长界面文案或跳过空状态使检查通过。
