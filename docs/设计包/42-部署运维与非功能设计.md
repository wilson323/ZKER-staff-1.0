# 部署运维与非功能设计

技术设计1.0｜2026-09-11｜`DEPLOYMENT_PROPOSAL / NO_SERVICE_DEPLOYED`。目标是可恢复的最小部署，实际环境、资源配额和服务版本尚待M0与压测确认。

## 1. 环境与部署单元

| 单元 | 开发/POC | 首期正式部署建议 | 扩容条件 |
|---|---|---|---|
| 统一Web与入口 | 本地开发服务，合成数据 | 静态资源+单一HTTPS反向代理 | 静态访问压力再用现有CDN；不缓存私有API |
| 应用API | 单应用进程，显式启用BPM和AI模块 | 模块化应用，可两副本；共享会话按底座机制 | CPU/数据库等待/连接数实测决定 |
| AI Worker | 单隔离进程，低并发及假外部服务故障注入 | 与应用分资源限额，可横向增减 | 队列等待、模型配额、预算和运行时长共同限制 |
| 关系库 | MySQL优先验证方言；独立临时库 | 私网持久化与恢复方案；是否HA由SLO决定 | 索引与连接池优化后再读副本/分区 |
| 缓存 | 复用底座兼容实现 | 私网、认证、限额；可丢缓存可重建 | 内存/连接与失效延迟实测 |
| 向量服务 | 所选底座已实现的Qdrant优先验证 | 私网、独立索引版本与备份/重建 | corpus量和过滤检索延迟决定扩容 |
| 对象存储 | 私有临时桶或合格开发存储 | 组织已有私有对象存储，按版本和保留策略 | 大文件/预览解析单独限流 |
| 日志/指标 | 本地受控日志与测试收集 | 接现有监控和告警渠道 | 不因首期建设全套可观测平台 |

表中Qdrant与显式启用模块是芋道条件性映射，其他候选须按37号2.2重新验证；MySQL不表示其BPM/AI初始化完整。芋道公开初始化缺口、官方附件附加使用条件见36号。不能直接执行上游默认启动脚本作为验收：默认未启用模块也可能启动成功。禁止拿“应用健康200”替代人员流程、知识检索、工具执行和交付的真实检查。

无需默认Kubernetes、服务网格、多地域双活、独立消息平台、独立图数据库。若组织已有这些平台可接入其标准能力；是否新增由测量与运维责任决定，不以架构图丰富程度决定。备选底座切换需同时更新版本锁、容器镜像、端口与数据迁移，不能只改后端依赖。

## 2. 网络、配置与秘密

浏览器仅访问HTTPS入口。API、Worker、关系库、缓存、向量库和对象存储管理面均不公开暴露；工具出站只允许已登记提供方和动作。内部回调验证服务身份、任务租约、fence和nonce，不能因位于内网免认证。公开文件原路径必须关闭或限定非敏感资源，避免鉴权代理旁路。

环境配置分为应用配置、资源引用和秘密。普通产品用户只选合格资源及简明偏好；管理员维护provider/模型白名单、网络出口、预算与存储配置，秘密由组织已有密钥管理/受保护注入提供。仓库仅放无真实值的示例schema，不提交.env秘密。审计secretRef操作，不记录秘密正文。

版本清单应含后端/frontend提交、JDK/Boot/引擎/AI BOM、Node/包管理器、数据库/向量/缓存镜像digest、模型ID/版本、提示/技能/工具/评估集版本和Schema迁移号。本次仅锁研究源码，不宣称这些组件已共同构建或已签名交付。

## 3. 容量演算与限流

以下用于POC规划，不是购买规格。假设峰值10个AI执行，每个平均120秒，则稳定到达率上界约`10/120 = 0.083次/秒 ≈ 5次/分钟`；突发量超过它会形成队列。实际服务时长分布、模型RPM/TPM、工具配额和长尾都可能降低可用吞吐，需用P95时长与真实约束重算。

若每次输入8000 tokens、输出2000 tokens，则10个并发在120秒均值下的示例吞吐约50000 tokens/分钟，须按提供方实际分别计算输入/输出限额与费用；不使用此示例当真实账单。预算预留基于上界，结算来自实际回执；未知账单保留待对账。租户/人员/工作/模型分别限流，拒绝或排队不能重复扣费。

关系库连接池与Worker并发分开。LLM调用期间不持有数据库事务连接；队列轮询批量有界，睡眠退避但及时响应停止。文件解析有大小/页数/压缩比限制，上传、解析和向量写入分别限额。检索集合增长时先测授权过滤后的召回与延迟，不因无过滤高QPS漂亮而忽略真实安全查询。

## 4. SLO、告警与可用性目标

候选目标需产品/运维负责人在正式环境确认；本次没有实测达标。

| 指标 | 候选目标/口径 | 验证或告警方式 |
|---|---|---|
| 交互API可用性 | 首期按99.9%月度目标讨论，排除计划维护须明示 | 按真实请求及业务错误分类，权限拒绝不算系统故障 |
| 常用只读API | 目标P95≤1秒（预热且指定数据量） | 同身份/权限下的真实待办、查询、文件列表 |
| 首个执行状态 | C06受理后目标2秒内可观察排队/执行状态 | 不是要求模型2秒出成品；源事件与SSE延迟分测 |
| 权限收紧 | 服务端新动作即时重查，事件/缓存尽快失效 | 撤权与迟到输出竞态测试，不能只测推送耗时 |
| 恢复目标 | 候选RPO≤15分钟、RTO≤2小时 | 库+文件一致恢复演练；采用能力和预算需负责人确认 |
| 未知副作用 | 进入UNKNOWN即告警并阻断依赖交付 | operation→工具回执→负责人核对闭环 |
| 费用与队列 | 超预算停止新派发；队列等待超阈值提醒运维 | 不把失败重试变成无上限费用 |

结构日志字段：traceId、operationId、tenant标识摘要、work/attempt、schemaVersion、action、stage、latency、resultCode、policyVersion。默认不收集提示全文、秘密、文件正文或受限工具响应；业务审计与调试日志分访问范围。健康检查分liveness和readiness：依赖不可用不一定重启整个服务，避免雪崩。

## 5. 发布与回退

发布包包含固定源码/依赖锁、模块清单、许可证/NOTICE、SBOM、Schema差异、配置差异、真实测试、迁移及恢复记录。先在干净环境复现构建，再迁移测试库、执行业务/权限/恢复回归；未固定底座时这些状态保持NOT_RUN。

灰度只影响明确的新请求/新使用点。进行Worker升级时先停止领取，等待运行到检查点或租约自然交接，未知写动作须查证；不能直接杀全部任务后盲目补跑。应用旧新版本同时存在时事件和Schema要双兼容。默认方法/提示/技能升级不得改在途ExecutionSnapshot。

回退应用二进制前确认数据库向后兼容；破坏性迁移不能靠回滚容器解决。使用expand/contract以及独立回填记录。若恢复历史数据库，先冻结外部写和新触发，按业务键对账已发生的外部效果，再由当前有权人员决定继续，避免重复下单/发信/审批。

## 6. 故障处置手册

| 故障 | 立即动作 | 恢复条件与责任 |
|---|---|---|
| 模型超时/额度不足 | 保留草稿与阶段产物，停止无界重试 | 平台运维确认配额；当前人可转人工；写动作先查效果 |
| Worker宕机/租约丢失 | 原fence回写失效，标记待恢复 | 运行负责人读取检查点和ToolEffect后以新租约继续 |
| DB不可用 | 停止受理正式写，返回503 | 数据负责人恢复并核事务/Outbox；不缓存审批写后补发 |
| 向量库不可用 | 知识检索显示不可用，保留已获准原始引用 | 知识负责人重建/恢复索引；不能以模型猜测代替知识 |
| 文件上传/解析失败 | 保留真实阶段与失败原因 | 文件负责人修复来源或重试；正式交付保持缺项 |
| 撤权/离岗 | 停新用权和输出发布，撤销旧会话 | 当前责任人重新确认资源/配置，不自动继承私人凭据 |
| 引擎与业务交付不一致 | 标记PENDING_COMMIT并冻结重复提交 | BPM与业务负责人按operation回读处理，不手工改ACT表 |
| 费用回执不一致 | 保留未知用量与相关逻辑动作 | 运维/费用负责人查账；不归零或重复扣款 |

## 7. 安装与运维验收边界

本文件是部署与运行设计，没有执行安装、启动、密钥授权、计划调度、备份恢复或生产发布。最终发布必须补齐真实版本、负责人、环境配置与对应证据；“容器存在”“接口200”“SDK返回成功”均不能单独通过业务验收。
