# 技术实施路线与验证矩阵

技术设计1.0｜2026-09-11｜`DESIGN_VERIFIED_ONLY / PRODUCT_TESTS_NOT_RUN`。按28号M0—M5细化；不新建另一套产品需求编号或完成看板。来源与技术映射见[本次技术追踪](../../validation/technical-design-map.json)。

## 1. 优先验证而非直接冻结当前主分支

36号本次研究改变了25号的部分前提：芋道当前固定分支及近两个tag都有Boot3/Flowable8组合冲突；公开初始化缺BPM/AI表，官方外部SQL有附加使用条件；RuoYi-AI整包含受限第三方技能；Plus已存在SnailAI模块，不能继续写成“没有AI基础”。原25号保留其研究时间，本技术包明确记录这些新证据，不静默把旧报告当现状。

因此将芋道作为有条件设计参照，而非已批准可构建基线。先验证RuoYi-AI排除受限材料并补齐等价能力的合格子集，利用其覆盖较完整的公开初始化建立可复现基准；再比较芋道的成熟OA收益与兼容/DDL/许可处理成本，Plus作为第三对照。每轮只对有依据的问题有限修复，不无限换依赖直到表面启动。

## 2. M0采用验证清单

| POC | 输入与动作 | 必须保存的真实证据 | 失败条件 / 出口 |
|---|---|---|---|
| POC-01 源码与许可 | 固定36号commit；列实际module、前端包、第三方skills和SQL来源 | digest清单、许可/NOTICE、SBOM及排除内容 | 受限内容不可剥离且无授权则淘汰该组合，不使用受限SQL附件补通过 |
| POC-02 同代兼容 | 按候选启用实际流程与AI模块；芋道另验证Boot3与Flowable7.2.x局部修订 | effective-pom、dependency tree、干净构建日志、实际启动模块 | 仅system/infra启动不通过；不同时大迁Boot4/AI2并声称最小改动 |
| POC-03 初始化 | 原公开SQL+独立合法扩展DDL，清点所有DO/Mapper/引擎表 | 干净库和升级库初始化、角色登录、表单/BPM/AI读写 | 缺表、方言错误、付费附件未授权或来源不明均不得通过 |
| POC-04 OA完整事务 | 两笔实例、领取/协作/审核/交付/接手，注入提交中断 | 引擎与扩展表同事务/明确受理恢复证据、唯一交付 | 引擎已推进但包丢失/重复激活、无恢复状态则失败 |
| POC-05 AI最小真实任务 | 一个获准模型+一个只读工具+一份可读资料 | 配置快照、真实调用、用量、产物、人员确认及刷新回读 | SDK安装/模型成功字符串不足；候选不等于业务完成 |
| POC-06 通用权限 | 跨租户、对象、动作、后台授权与人员读取；文件旧URL绕过 | HTTP正文/文件/检索/SSE/缓存负例及撤权迟到输出 | 前端隐藏有效但原URL可读、后台资料进入用户对话则失败 |
| POC-07 恢复幂等 | 重复请求、Worker崩溃、网络未知、改派后迟到回执 | 稳定operation、fence、目标业务键和外部回执 | 重复业务效果、越权重试或费用归零则失败 |
| POC-08 UI与组件 | 固定前端提交与真实API，检查22页与字段、390/1024/1440 | route/组件/DTO映射与浏览器原始证据 | 演示站、截图或.d.ts存在不等于实际路由可运行 |

M0输出具名技术决策、精确版本锁和已知缺口，而不是自动宣布所有需求已实现。未授权安装/真实外发/生产动作在相应后续实施任务准备可审核方案后办理；本轮仅交付以上验证设计。

## 3. 分期与依赖

| 阶段 | 依赖 | 可交付切片 | 不可省略的出口 |
|---|---|---|---|
| M0 | 研究36及上述POC | 冻结可构建底座、合法初始化、模块/API映射 | 真实编译/启动/最小OA+AI与权限负例，成本再估 |
| M1 | M0 | 登录→同人两实例→本人配置→快照→真实产物→确认提交→刷新回读 | 不串实例、配置保存不执行、断线重连和人工路径 |
| M2 | M1 | 人员分工、贡献、来源变更、独立审核、正式交接 | 旧版本、自审、不可读附件、重复提交和转办负例 |
| M3 | M2 | 三类市场复制/引用、文件/知识、本体与简明偏好 | 凭据不复制、可见/采用/使用分判、来源撤权与字段合规 |
| M4 | M3 | 受限分析、主动事件、周期草稿、工具恢复与团队执行 | 指标口径、无样本/无权/超时、去重/停止/UNKNOWN闭环 |
| M5 | M4 | 真实评估与试用、运行质量、升级回退和运维 | 业务无退化、独立复核、试用回执、恢复/容量/用户任务验证 |

这是同一完整产品的推进顺序，不是删功能授权。需要某项能力更早时必须把其权限、数据和恢复依赖一并前移。无团队/工期数据，不编造人日或“复用百分比”；按实际POC记录接入、补DDL/适配、重构、验证和长期维护成本再排期。
