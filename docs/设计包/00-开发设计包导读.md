## 2. 开发必须共同理解的七个设计决定

1. **人责不变，Agent独立分配。** 执行人、协作人都是任务角色；数字员工归属、使用权、当前分工、结果责任分别管理。“写作人”若指材料作者，按内容编写分工处理。
2. **多人独立AI执行采用合法独立工作单元。** 保留一个WorkItem一个active AgentAssignment。临时协作建议复用合法AD_HOC创建路径并关联主工作；固定流程职责建成SOP节点。
3. **对齐业务基线，按人裁剪上下文。** 共同目标/约束/确认事实/文件版本一致，私人资料和连接身份不共享；不要无条件转发完整对话。
4. **“已写文件”不等于“数字员工已读取”。** ContextManifest、执行快照、装载证据、公开理解检查和业务检查分别存在，并沿唯一DSH边界验证。
5. **版本变化影响依赖者。** 设备清单v2使依赖v1的预算待重核；其他无依赖工作可继续。旧Assignment、旧上下文及旧fence不能提交当前结果。
6. **贡献、审核、正式交付和接手分开。** 数字员工产出候选，协作人确认贡献，主执行人汇总，指定审核者决定，ResultCommit保存合法业务完成，下一人重新授权后接手。

7. **员工市场按权限复制使用。** 员工可以直接采用获准的数字员工、技能与工具，加入本人资源并配置到自己的节点；浏览、复制、编辑和使用分别授权。已有条件齐备不重复申请，缺本人连接或其他依赖时明确恢复。复制不带原作者私人内容或凭据。

## 4. 如何进入开发

先由对应开发切片读取原需求ID、US故事、页面P编号、流程F编号、接口A编号与数据约束，核对当前合同和消费者，把增量合入现有TaskPacket及非重叠claim。优先接通人的工作闭环，再验证两人各自选Agent的上下文和贡献链，最后扩展全域资源、自动化与条件能力。

本包的字段和接口增量是明确的设计提案；未冻结到现有正式合同的部分需要在B0/B对应切片完成兼容与消费者设计，不可直接修改生产数据库。没有未解释的“先另写总设计”步骤，也没有把本次文档交付当成产品实现完成。

## v2.6 产品主旨、B/S与字段核查

本项目是以 OA 工作流为基础的企业 B/S 协作软件：流程连接人、责任和任务，由承担人在自己的任务内配置数字员工。业务发起 → 人员待办 → 本人配置数字员工 → 执行与确认 → 审批或交接 → 下一位承担人。既有平台能力全部保留。
