## 2. 每个开发切片必须交付什么

| 层 | 必交材料 | 通过证据 | 不足以证明 |
|---|---|---|---|
| 需求/设计 | 对应原ID、故事、页/状态、数据、命令、恢复 | 追踪完整，无相互冲突字段/状态 | 大段概述 |
| 合同 | Schema/OpenAPI/事件/状态与消费者变更 | 标准校验、兼容差异、正负例 | 生成类型文件 |
| 数据 | 当前迁移head、约束、旧数据策略、回退 | 真实PG迁移/回读/并发/跨租户负例 | 内存Mock或空库 |
| Provider | 既有服务内实现和鉴权/事务 | 实际路由、状态码、字段及业务效果 | 代码存在 |
| Runtime | 既有Adapter对接、快照与上下文消费 | 受控真实DSH执行、引用和产物 | 写入prior-context.json |
| UI | 真实角色导航、字段、动作、错误恢复 | 浏览器执行任务、刷新和深链接 | 静态截图或原型按钮 |
| 真实依赖 | 测试租户/应用/设备/模型调用 | 可回查真实目标对象、回执和无重复效果 | “已授权”或HTTP200 |
| 发布 | 对应环境、回归、备份恢复与试点 | 实际版本和验收记录 | 本包完成或局部19单测 |

## 3. 最小完整业务验收脚本

使用受控测试租户和虚构设备采购案例；人A主执行、人B技术、人C预算、人D独立审核，至少两人实际使用不同合格 Agent。不能复用一个最高权限账号模拟全部角色。

1. A 从本人待办领取主任务，页面显示职责、输入、交付和下一岗位。
2. A 请求 B/C 协作，B/C 各在自己的合法子工作中选择 Agent；数据库确认父子关联且每项仅一个有效分配。
3. 为 A/B/C 准备不同授权投影，共同设备数量/目标一致，私人笔记和连接身份互不泄漏。
4. 把关键规则放在第八条以前及长消息第512字符之后；真实执行必须仍遵守。校验最终动作和产物，不能仅询问“你理解了吗”。
5. B 提交技术清单 v1，C 据此形成预算。A 有权确认清单 v2 后，C 的预算被标记需重核，旧候选不能正式提交。
6. C 核对变化，以新 ContextBinding/Attempt 或真实支持的更新重新执行；发生过的外部效果先查证，不能重复创建。
7. A 接受专业贡献并汇总；D 仅在自己的 assigned request 中审核，不得自批、跨任务读取。
8. 提交时故意改变人员授权或工作 revision，验证拒绝旧请求并保留草稿。
9. 条件恢复后重复相同提交和事件投递，验证只有一个合法结果和一次下游激活业务效果。
10. 下游先模拟必需资料不可读，展示可恢复阻塞；恢复授权后接手，同一包内容和历史引用不变。
11. 断线重连、进程重启、模型额度不足及连接过期分别验证；不让“运行成功但无产物”通过完成守卫。
12. 在所声明的角色/屏宽/状态组合中核对 UI；实际执行多少组合就报告多少，不以样本推全量。

该脚本与原 V01–V28 场景联合使用，完整场景和153条需求之间按此次发布范围登记覆盖；不推断全域能力已完成。

## 4. 非功能要求与指标字典

| 指标/要求 | 定义及来源 | 解释 |
|---|---|---|
| 业务完成率 | 窗口内通过业务完成守卫的可完成工作项 / 窗口内进入相同验收口径的工作项 | 取消、仍运行、试验任务单独列示，不暗改分母 |
| 运行成功率 | Run=succeeded / 已进入运行终态的Run | 仅技术指标，与业务完成率分别展示 |
| 首次合格交付耗时 | 从有权人员接收任务到首次正式通过提交 | 输出分位数与样本量，不只平均值 |
| 返工率 | 因交付缺陷退回的已审核交付 / 被审核交付 | 需求变更与执行缺陷区分原因 |
| 交接等待时间 | 包合法生成至下游满足接收条件并确认 | 等权限、等人、等资料可拆原因 |
| 必需上下文缺失率 | 因必需上下文缺失被阻止的启动 / 节点有效启动请求 | 同一幂等重试去重 |
| 过期提交阻止 | 被基线/Assignment/fence守卫拒绝的提交数，及经检查的过期请求数 | 拦截数本身不代表质量提升 |
| 上下文应用延迟 | 授权相关业务变更发布到受影响执行应用新基线 | 未应用者作为未完成样本，不从分母删除 |
| 费用 | 原始模型/工具用量按实际价格来源和时间核算 | 无价格来源时只显示用量，不假估费用 |
| 重复副作用 | 同一幂等业务意图产生超出合同允许的重复外部对象/动作数 | 用回执和目标查证；目标为消除重复但不伪造零值 |

容量、延迟、成本和可用性目标需要真实试点基线与当前部署约束后冻结。建议测典型/长上下文、并发领取、多人贡献、长事件流和大文件引用；本设计不虚构并发用户数和 SLA。

鉴权、存在性隐藏、租户过滤和限时授权遵守既有合同。可访问性、中文/英文长文本、200%缩放、键盘和断点依UI设计进行。秘密不得出现在前端、会话、普通诊断导出或上下文中。
