# 业务不变量、权限与验收夹具

开发文档包0.1｜`DESIGN_ORACLES / PRODUCT_TESTS_NOT_RUN`。本文件把27/34/39/41的关键规则转成输入、预期和实际验收方法。合成夹具不代表真实鉴权实现；不得将参考表校验通过写入原30号AC的产品通过状态。

## 1. 不变量与执行层

[invariants.json](../../contracts/invariants.json)包含24项不变量，完整覆盖身份、路径/内容、执行用权/发布、轮次、版本、自批、交付、幂等、未知效果、撤权、多实例、下游资料、取消、关系图、进化、计量、配置撤销、分析空值、主动触发、市场、OA同步和权限不可用。

| 守卫层 | 必须判断 | 不能代替它的层 |
|---|---|---|
| 会话/身份 | 有效人员、当前租户、任职与状态 | 浏览器传actor/tenant、插件声明 |
| 应用命令 | 对象关系、动作资格、责任轮次、目标版本 | 按钮隐藏或角色名称 |
| 读取投影 | 对象发现、字段/正文/摘要、用途和受众 | 已获执行Grant |
| 执行前与每次工具调用 | 服务身份、来源用权、目的地、动作、限额、期限、fence | 启动时的一次性预览 |
| 发布和下载 | 来源版本、受众、发布策略、当前授权 | 模型自述“已脱敏” |
| 数据事务 | revision/唯一键/同租户关系、真实OA推进 | 客户端预检通过 |

低代码表单和插件的入口也经过这些守卫；可配置规则不能覆盖平台不变量。商务/研发只是任意两个主体/资源范围的例子，测试不依赖部门名称。

## 2. 人员权限与后台权限夹具

[permissions.json](../../contracts/fixtures/permissions.json)的16组真值表有固定输入与预期，覆盖READ、PATH、EXECUTE、RELEASE。所有输入为模拟事实；产品测试需从真实会话、Grant、来源和策略服务获得这些事实，不能接受HTTP客户端提交这组布尔值。

| 代表场景 | 预期 |
|---|---|
| 有路径发现权，无正文读权 | 只返回受控阶段和通用“受限节点”；无标题、附件名、摘要、片段 |
| 无路径发现权 | 不返回该节点，不返回隐藏节点计数/分支长度；可能影响路径时给获准的抽象连接 |
| 人不能读，来源有权者授予后台限定用权 | 服务可在指定任务、用途、目标和期限内使用；人端不收到原文 |
| 人能读，无后台用权 | 人员预览可用；AI启动/工具使用拒绝 |
| 后台完成，有独立受众发布决定 | 只返回新发布副本/已审查结果；不能返回原始来源 |
| 授权撤回或政策不可用 | 撤权拒绝并清理；不可用返回503，不能伪造EMPTY_AUTHORIZED |

发布判断必须含来源传播关系。自由生成摘要可能重述受限事实，不能因“摘要”二字默认降级敏感性。受限内容的统计、图表、异常文案、文件标题、引用哈希和关系路径也需评估是否可披露。

## 3. 状态机、时序与原子性

[state-machines.json](../../contracts/state-machines.json)记录合法转换和关键边守卫；[states.json](../../contracts/fixtures/states.json)覆盖逆向终态、未知重跑、取消迟到、下游阻塞和审核过期。状态合法边只是必要条件，不表示执行权限或证据已经满足。

| 竞态 | 预置与动作 | 必须观测的真实结果 |
|---|---|---|
| 双人领取 | 同revision并行C03 | 一次成功、一次409；OA承担人唯一 |
| 预检后来源变更 | C11 check后修改Baseline再submit | 409/422；delivery未确认；重新核对提示 |
| 转派后旧Agent迟到 | 增epoch/fence后回调旧结果 | 可留审计，不成为当前候选/交付 |
| 同键并发提交 | 同主体同意图键同时C11 | 同operation/delivery，不能推进两次OA |
| 同键异载荷 | 改artifactRefs后重用key | 409；原交付内容不变 |
| 工具已写但回调丢失 | 外部服务落单后超时 | UNKNOWN，查询业务键恢复，外部记录只有一份 |
| OA推进回执丢失 | Outbox消费已推进但未确认 | PENDING_COMMIT，查证同实例/节点，不重复创建下游 |
| SSE撤权/HTTP晚到 | 取内容中撤权，旧响应延迟返回 | 服务拒绝后续内容；客户端丢弃旧代次并清理缓存 |
| 必需附件撤权 | 上游交付后下游点击接手 | BLOCKED，无接手回执，无“可开始”假状态 |
| 插件升级或停用 | 正在运行时发布新版本/撤销工具 | 原执行固定版本；安全撤权仍终止新调用并查证已有副作用 |

产品实现测试应设置屏障/可控时钟/故障点复现时序，不能用随机sleep碰运气。独立检查数据库、OA原始任务、调用台账和用户界面；只看一层日志不足以判定成功。

## 4. 合成种子与安全哨兵

[seed.json](../../contracts/fixtures/seed.json)提供两个租户、三个虚构成员、同人同模板两个实例以及三种canary。它不是初始化SQL，不含真实凭据。M0用底座原生配置创建测试账号和授权，然后登记真实ID映射；禁止在产品中硬编码demo身份。

在测试环境的私有来源、另一实例、另一租户分别写入不同canary。收集**该测试主体**的HTTP响应、SSE、DOM、可导出日志、查询缓存和预览数据，断言不出现未获准canary。再做语义复述检查，避免仅去掉字符串但仍泄漏事实。测试报告只能保存虚构数据和脱敏证据。

## 5. 层级与完成判定

| 层级 | 本包产物/执行方式 | 能证明 | 不能证明 |
|---|---|---|---|
| L0 文档/合同静态 | 本轮独立检查脚本 | 引用、必需字段、类型、样本预期、映射一致 | 后端真实实现 |
| L1 参考规则 | 权限真值表/状态边样本核对 | 设计规则内部无矛盾 | 生产策略服务会正确执行 |
| L2 单元/组件 | 采用后运行真实领域服务和UI组件 | 本地守卫/显示行为 | OA/存储/模型端到端 |
| L3 集成/数据库 | 真实HTTP、数据库、引擎、受控工具服务 | 并发、事务、鉴权、回执 | 真实业务用户已认可 |
| L4 产品验收 | 原72项AC + EW + AI场景，真实浏览器 | 对应已测试场景的业务闭环 | 未测场景或生产就绪 |
| L5 发布与运维 | 备份恢复、负载、故障、审计、部署证据 | 指定发布范围的就绪 | 永久无故障 |

每条证据记录taskId、需求/AC/EW、源码/配置/Schema/数据版本、命令、运行时间、退出码、实际结果、产物哈希、未覆盖项。未执行保持NOT_RUN；BLOCKED/PARTIAL不能汇总成成功。P0权限泄漏、重复外部副作用、错误交付或自批任何一个成立，阻断对应切片。

## 6. 反思后的断点与修正

| 容易遗漏的断点 | 本包处理 | 实施时还须证明 |
|---|---|---|
| 工作台只换页面但会话/草稿仍串实例 | 按主体/租户/工作/轮次/代次分键，切换取消旧请求 | 浏览器切两实例与多标签并发 |
| 完成检查之后版本变化 | 提交事务再次比较，预检有期限 | 用竞态实际使旧check失败 |
| 插件已启用但任务不可用 | 安装、连接授权、动作Grant、任务用途、执行回执五层状态 | 一个实际任务而非平台注册数量 |
| 低代码配置直接执行任意表达式 | 受控Schema/节点白名单，不下放核心守卫 | 导入恶意配置及权限增量拒绝 |
| 通用Operation没有真实业务成果 | 需结果引用、可读取版本内容和真实回执 | 对应C01/版本资源读取/文件校验 |
| AI自评通过自动发布 | 独立业务评估、固定指纹、受控试用、人员发布 | 版本变更使旧评估STALE |
| 字段字典完整被误解为迁移完成 | 明确候选DDL和逐表复用计划 | MySQL真实约束/执行计划/恢复演练 |
| 173行相同链接冒充实现覆盖 | 精确动作+领域+页面+候选记录；保留原验收 | 采用后再补真实源码及测试文件证据 |

## 7. 使用现有审查流程

沿用REVIEW.md的产品、权限、交付、依赖四个视角，将发现记录在当前任务review。无需新审批平台或多Agent机制。普通低风险配置可复用已有维护权限；发布外部插件、敏感授权、迁移与真实外发按当前具体范围处理。模型的自述不能替代Validator直接读取产物。
