# 接口、事件与集成技术设计

技术设计1.0｜2026-09-11｜`PROPOSED_API / NO_ENDPOINT_IMPLEMENTED`。C01—C31保持[27号](27-逻辑数据模型与接口契约.md)语义；下表是拟议路由，不是已存在后端API或冻结OpenAPI。最终DTO在M0与选定底座对齐后生成类型，禁止将任意JSON直通为业务命令。

## 1. 协议与公共字段

浏览器同源HTTPS调用`/oa-api/v1`。身份复用system会话；若部署采用cookie则启用CSRF/Origin校验、HttpOnly/Secure/SameSite策略，跨源仅列允许来源；不用URL参数携带长期token。路径ID只是资源引用，服务端解析tenant、subject、任职和对象权限；不得信任浏览器传actorId或tenantId冒充主体。

写入使用`Idempotency-Key`（同一用户意图重试保持不变），并携带expectedRevision、responsibilityEpoch和目标版本；含资源集合的正文限制大小/数量。合法并发冲突为409；若使用If-Match则412，不能同接口混用两种约定。只读请求允许有限退避，写请求超时先查operation。

返回外层沿用底座统一响应，经唯一前端adapter转换；本模块业务data内含requestId、operationId、status、revision、allowedActions及currentSourceWatermark。HTTP 2xx只表示协议或受理状态，status必须区分QUEUED/PENDING_COMMIT/CONFIRMED/FAILED/UNKNOWN。错误映射保留code、可公开message、fieldErrors、retryable和recoveryAction；无发现权统一404且不返回对象名/计数。

## 3. 三个关键写入示例

以下ID与digest为演示占位值，不是真实凭据或有效调用。正式版本字段必须在服务端核对，不能仅验证格式。

```json
{
  "command": "C06.startAttempt",
  "workId": "work_A",
  "expectedRevision": 12,
  "responsibilityEpoch": 3,
  "bindingVersion": 5,
  "contextPreviewRef": "preview_17",
  "executionMode": "ASSISTED",
  "outputContractVersion": 2
}
```

C06重新计算权限和输入，preview不是授权。响应202的data包含`operationId、attemptId、status=QUEUED、snapshotDigest、eventCursor`。相同幂等键重试返回相同attempt；同键异内容409。无合格资料不创建可执行Attempt，返回缺项与当前有权恢复入口。

```json
{
  "command": "C11.submitDelivery",
  "expectedRevision": 16,
  "responsibilityEpoch": 3,
  "candidateVersion": 4,
  "completionCheckId": "check_21",
  "approvalRef": "review_9",
  "artifactSetDigest": "sha256:EXAMPLE",
  "baselineDigest": "sha256:EXAMPLE",
  "attemptRef": "attempt_7",
  "attemptFence": 8
}
```

人工完成时attemptRef/fence不是必填，改用合同允许的manualProvenance及人员证据；人工路径仍校验成果、版本和必要审核。C11同步原子成功才返回CONFIRMED和deliveryId；跨边界返回PENDING_COMMIT，不把审批回执直接当已交付。C12核接收责任及必需附件当前可读，重复返回同receipt。

```json
{
  "command": "C27.applyProposal",
  "proposalId": "proposal_2",
  "expectedRevision": 7,
  "selectedChanges": [
    {"fieldPath": "outputFormat", "value": "CHECKLIST"}
  ],
  "scope": "CURRENT_WORK"
}
```

C27只接受白名单字段，禁止角色、权限和tenant等越界字段；单项采用仍校验组合，不允许跳过必需输出。撤销传原mutationRef与当前expectedRevision，调用同一C04设置事务；存在后续修改则返回可披露冲突，不覆盖新值。

## 4. 事件信封与SSE

```json
{
  "eventId": "evt_41",
  "schemaVersion": 1,
  "type": "AttemptStateChanged",
  "aggregate": {"kind": "Attempt", "id": "attempt_7", "sequence": 6},
  "sourceRevision": 12,
  "occurredAt": "2026-09-11T12:00:00Z",
  "correlationId": "op_8",
  "causationId": "evt_40",
  "data": {"workRef": "work_A", "state": "WAITING_REVIEW"}
}
```

内部tenant字段只在可信服务边界流转；人员SSE返回当前主体投影，不能原样广播内部事件。类型至少包含WorkResponsibilityChanged、BindingInvalidated、AttemptStateChanged、ToolEffectUncertain、ContextChanged、ContributionDecided、ReviewDecided、DeliveryConfirmed、HandoffReceived、ResourceAccessChanged、UsageSettled。消费者inbox按source/eventId去重，aggregateSequence发现缺口就回权威快照补齐，不能用迟到事件倒退UI。

拟议`GET /work-items/{workId}/events`只观察。EventSource使用同源会话，服务端发送事件id及心跳，客户端带Last-Event-ID恢复；游标绑定主体/任务/策略。断线保留草稿、显示重连状态；历史窗口外返回reset/snapshotRequired，由客户端获取当前WorkspaceView。权限变更立即使旧订阅和响应代次失效，新的事件逐次重验；不在URL放长期凭据。

敏感后台运行不流式透传原始token。前端只见允许公开的阶段事件；候选内容按具体接收者和版本完成发布检查后再显示。文档标题、工具名/参数、异常堆栈也可能含敏感内容，不作默认事件字段。SSE链路不能暗含再次开始Attempt或提交命令。

## 5. 外部连接、回调与文件

连接动作由provider、action schema、version、scope、risk、timeout和idempotency能力定义。连接存在/账号已授权/动作获准/当前任务可用/实际回执分别返回。个人密钥和服务密钥只保留secretRef，通过任务限定身份解引用；日志与API响应不返秘密。

Webhook校验来源签名/时间窗/nonce并记录去重；只读回调也验证对象关联。IM用户映射真实组织成员和具体工作，歧义先给候选由人选；聊天“同意”不能直接解析成独立审批。外部action未知时GET operation查证，不把超时自动转换为新请求。对方不支持幂等时，用业务键查证；无法查证由当前有权人员恢复。

文件通路单独鉴权：本次36号发现原infra下载接口可绕过登录与租户过滤，因此不能把其公开URL用于受限产物。必须限制或替换原公开下载路由、关闭存储公共访问，前端只拿`/artifacts/{id}/versions/{version}/content`或一次性短期授权代理引用。Range、缩略图、历史版、下载与预览都重验。不能只包一层新接口却保留原URL绕过路径。

长连接和大文件经网关配置适当超时/流缓冲，设置下载Content-Disposition与安全MIME；HTML/Office预览在无同源权限沙箱中，解析失败返回真实状态。上传回调核实际对象digest和租户命名空间，不信任客户端文件名或确认上传正文。

## 6. 接口冻结与验证

实施时为每个action生成精确request/response Schema、字段必需性、错误、幂等和权限例；不能用一个`additionalProperties=true`对象冒充完整契约。OpenAPI及前端生成类型共同版本化；兼容新增字段优先，删除/改义需要版本迁移。事件schema升级使用双消费者验证，不能靠“忽略未知字段”容忍业务含义改变。

合同测试覆盖同键异载荷、未知对象/租户、旧epoch、撤权迟到响应、必需附件不可读、重复回调和断线重连。契约结构通过不等于真实数据/权限验收；43号给出逐层证据。
