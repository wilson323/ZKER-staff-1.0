## 1. 依赖驱动的实施阶段

阶段号与历史需求优先级分别管理。每个阶段纳入的需求须从30号追踪选择并记录具体实现与证据；没有覆盖的需求保持待实现，不能因试点结束而删除。

| 阶段 | 前置 | 可交付切片 | 必须通过的出口 | 失败处理 |
|---|---|---|---|---|
| M0 底座验证与等价映射 | 研究快照、产品基线 | 固定前后端/BOM、选入模块、身份/OA/AI启动；逻辑到物理映射；实际交付依赖清单 | 干净构建与同一环境下OA/AI可用；许可和兼容疑点按实际依赖解决；基线无未解释削减 | 优先局部解决；若需大规模适配，对备选执行同一用例并记录差异 |
| M1 单人真实任务闭环 | M0 | 发起多笔实例、本人待办/领取、人工与AI配置、输入快照、真实运行/产物、人员确认及提交 | 一人同时两笔业务隔离；刷新/重启可回读；无权和旧版本被拒；人工路径可完成 | 修复事实归属和绑定，不以模拟返回替代 |
| M2 多人协作与交接 | M1 | 独立协作任务、各自AI、贡献/变化重核、审核、正式交付、下游接手 | 多人真实账号在同实例完成；旧预算、过期审批和迟到运行不能提交 | 保留历史候选与故障证据，从明确版本恢复 |
| M3 OA与资源治理完整化 | M2 | 会签/或签/加减签/代理/退回/补偿；三类市场；资源/知识/组织授权与离岗联动 | 28条OA、10条市场细化及各角色正负例通过；已有能力映射完整 | 失败分支保持不可用或阻塞态，不能隐藏需求 |
| M4 高级工作能力 | M1及相应领域依赖 | 团队、执行方案、自动化、IM/专家/A2A、设备、记忆与经验改进、API扩展 | 每种启用能力有独立真实调用和异常恢复，回到同一业务提交规则 | 条件未满足不作为正式可用；保留能力与依赖追踪 |
| M5 发布与持续验收 | 所有发布范围需求通过 | 容量、隔离、可访问性、恢复、升级、用量、审计、试点价值 | 发布范围无未处理关键失败；恢复演练和实际业务签收完整 | 保留回退路径及数据；不以单一测试绿色宣布生产就绪 |

执行团队可在互不冲突且具有明确数据/接口前置的领域并行工作，但不另建本项目尚未采纳的任务平台、writer lease或旧仓治理。开发任务必须记录具体工作目录与代码版本，防止相邻项目混用。

## 2. 验收环境与代表性数据

代表性案例采用“采购方案协作”与“合同审查”两类流程，属于本次设计建议的试点组合；企业最终模板另行确认。采购、合同、报销、人事四类字段结构均保留候选验证。

- 至少两个租户的测试身份；同一租户包括发起人、甲主执行、乙技术、丙预算、戊写作、丁独立审核、下游接收人、主管、资源维护及各管理域角色。测试账号不是生产真实人员。
- 同模板同日创建A、B两笔；另建合同C。同一人在A执行、B协作、C审核，并在A承担两个不同工作时也能区分轮次。
- 设备清单v1/v2、预算v1/v2、写作稿和正式方案各有真实文件版本；预算v1依赖清单v1，v2改变数量以制造可判定的过期场景。
- 三类市场资源各准备：可看不可复制、可复制不可运行、依赖齐备、私有依赖、下架/安全撤销、来源升级等对象。
- 配置个人连接、组织服务连接和有限委托；外部效果使用可查证的测试系统，具有真实调用记录。涉及真实外部发送或费用前取得相应任务授权，不能用本设计文档代替授权。
- 准备正常、拒绝、网络中断、重复/乱序事件、取消、进程重启和未知外部结果。可使用受控故障注入；任何替身/模拟必须标注范围，并另补真实依赖验收。
- 固定浏览器版本、屏宽390/1024/1440、业务时区与跨夏令时日期；保留代码/数据库版本、启动进程和配置来源，不记录明文秘密。

## 3. 跨域产品验收用例

以下AC编号是场景级验收集合，用于跨需求关联，不替代153项各自原有验收，也不声称本版72个用例覆盖所有组合。每项研发验收还须逐条执行29号原验收及对应MC/OA/角色负例。

| 编号 | Given / When | 必须得到的结果与原始证据 |
|---|---|---|
| AC-01 | 固定底座及真实启动版本，员工从正常入口登录并打开本人任务 | 真实页面、监听进程/构建版本、服务端任务关联一致；不强制旧8765端口，不使用静态占位 |
| AC-02 | 同人跨三流程、多实例且同实例有两项任务，筛选/分页/刷新 | 每项可见任务不漏不重；任务数、实例数、流程类型数独立；无权标题和统计不可枚举 |
| AC-03 | 两个候选人在不同浏览器同时领取同一任务 | 一个成功，另一方冲突并回读当前归属；底座只存在一个有效主承担关系 |
| AC-04 | 同模板同日发起两笔，相同幂等键重试首笔，异载荷复用该键 | 新意图产生不同实例；同意图返回原实例；同键异载荷拒绝；数据库和事件无重复 |
| AC-05 | 一个实例配置顺序、并行会签与或签，合法/迟到参与者提交决定 | 各阶段按固定规则激活；或签只有一个有效结束决定；回执对应人员与目标版本 |
| AC-06 | 运行中转办、委派、退回、新轮次，并投递旧执行回调 | 新责任可回读；旧人/旧fence/旧审批拒绝；新承担人重新确认配置，历史保留 |
| AC-07 | 对具体实例催办、延期、抄送与升级，触发重复请求 | 只影响该实例未决工作；冷却/去重生效；已读不审批；延期和升级分别有记录 |
| AC-08 | 缺合格人员、人员离岗/休假、无权代理 | 明确待解决事项和接手者；禁止随机分配/越权代办；任务与资产交接影响可核对 |
| AC-09 | 模板允许人工、协助与有限自动执行，分别保存和开始 | 人工无模型凭据仍可交付；配置持久化与实际运行版本相同；保存不自动执行 |
| AC-10 | 从个人、共享、推荐选择资源，缺必需项/参数冲突/无权候选 | 合格配置真实运行；缺项明确阻止；个人偏好不覆盖节点硬条件或改变其他任务 |
| AC-11 | A/B共用同一数字员工版本，分别上传、聊天、运行并取消A | 工作空间、对话、预算与取消信号隔离；B继续；记录能还原各次实际输入 |
| AC-12 | 运行中断网、重连、暂停/恢复、停止，制造资源/模型失败 | 流式进度真实且不重跑；不支持的控制不假报成功；草稿/阶段产物及可恢复点保留 |
| AC-13 | 甲请求乙/丙/戊协作，对方接受/拒绝/过期 | 接受产生独立合法工作与责任；各自选择AI；拒绝/过期回甲处理，无孤立或循环工作 |
| AC-14 | 协作人确认贡献，甲接受或退回，尝试替协作人提交 | 合法贡献/接受记录完整；主项未自动结束；他人私人配置与确认权不可冒用 |
| AC-15 | 接受预算v1后确认清单v2，另有无依赖工作B | 预算及依赖文稿待重核，旧贡献提交拒绝；B继续；重核后形成新版本并保留旧来源 |
| AC-16 | 上下文含共同事实、私人笔记、超长历史及必需约束 | 各接收者基线一致且私有内容隔离；长历史不截掉必需约束；装载有可信运行证据 |
| AC-17 | 原资料缺失/撤权/过期，提交摘要冲突，测试恢复和缓存 | 必需输入阻止派发；恢复重授权；旧缓存不可继续引用错误事实；公开差异有来源 |
| AC-18 | 向上下文/待办消费者发送重复、乱序和缺口事件 | 去重、防倒退、缺口回读；最终投影与权威版本一致；消息已读不等于装载 |
| AC-19 | AI成功但无产物、检查失败或未知外部结果，尝试正式提交 | 不产生有效DeliveryCommit；明确具体缺项；不能以HTTP200或运行成功放行 |
| AC-20 | 丁审核候选v2后候选变v3或由本人自批 | 旧批准不适用，自批拒绝；新审核明确绑定当前版本，意见/咨询不替代回执 |
| AC-21 | 合法正式提交，注入重复请求及提交/下游激活之间重启 | 唯一有效交付/包和后继任务；中间态可查证恢复；UI不提前显示业务完成 |
| AC-22 | 下游收到包但必需文件无读权，补齐后接手 | 先BLOCKED再合法接收；交接包内容未变；收到通知不计已接手 |
| AC-23 | 正式交付后出现迟到贡献、撤回资料、取消或外部补偿 | 不改历史包；形成补充/返工/补偿关系；通知受影响者且有责任和回执 |
| AC-24 | 新建数字员工、自然语言草拟、修改、试验、发布及资源绑定 | 真实内容摘要随版本变化；发布、读取和执行一致；绑定可回读并可撤销 |
| AC-25 | 数字员工详情、多种关系搜索、归档/恢复、导出/导入/升级 | 草稿可继续；关系不重复；包无秘密；新版不改在途；依赖影响与批量结果可核对 |
| AC-26 | 创建/导入技能，包含坏Schema、缺依赖、冲突顺序，再隔离试验发布 | 错误定位；导入不执行；试验不产生正式副作用；参数进入真实调用；更新/回退可追溯 |
| AC-27 | 员工从任务进入三类市场，分别搜索、详情、复制使用/编辑/引用 | MC-01—MC-10逐条验证；按钮与服务端动作一致；复制或引用语义正确并回到本人任务 |
| AC-28 | 复制资源含作者私人记忆/文件/凭据/不共享依赖 | 副本无私人内容；缺项就绪状态真实；资源可见不等于能运行；同源不同人的副本隔离 |
| AC-29 | 双击采用、响应中断、来源升级/下架/安全撤销 | 查询同一操作得到唯一结果；部分失败明确；升级不覆盖私人修改；撤销阻止未来不合法使用 |
| AC-30 | 配置MCP/HTTP工具，测不可达、零工具、不兼容及个人/服务身份 | 各状态分别有来源；真实只读调用能核对账号与范围；普通页面和日志无秘密 |
| AC-31 | 外部写入需要确认，参数改变、超时、重复回调和重试 | 旧确认不覆盖新参数；未知先查证；外部实际对象无重复；回执与交付可交叉核验 |
| AC-32 | 连接到期、撤销、轮换、离岗，运行继续或恢复 | 下一使用点重新授权并阻止失效动作；本人修复连接后回原任务，不共享原作者账号 |

| AC-34 | 固定业务集测试关键词/语义/混合检索、同义/无答案/更新及引用撤权 | 报真实召回、支持关系与无答案；引用可打开精确片段；撤权后点击和缓存拒绝 |
| AC-35 | 个人/Agent/团队/项目/渠道记忆检索、纠正、忽略、保留冲突 | 本次使用可解释；私人记忆不串人；失效不被旧缓存带回；数据处理请求有实际状态 |

## 4. 验收证据规范

每个产品用例保存：用例及需求ID、执行时间、代码/部署版本、测试租户与角色的非敏感引用、前置业务对象与版本、具体动作、HTTP/服务端原始结果、数据库或权威回读、浏览器截图/录制、外部回执、期望/实际差异及结论。敏感正文最小化，不保存密码、Token、Cookie或模型内部推理。

证据层级分别记录：文档结构、Schema/静态、单元、集成、真实依赖、浏览器、故障恢复、生产/客户业务。一个层级的通过不替代另一个。测试结果状态采用PASS、FAIL、BLOCKED、NOT_RUN，禁止把未执行改为跳过后汇总通过。

每条需求的真实实施记录至少为：

```yaml
requirement_id: NC-07
source_requirement: 10-需求追踪数据.json
implementation_status: NOT_IMPLEMENTED
design_refs: [26-完整产品设计文档.md, 27-逻辑数据模型与接口契约.md]
implementation_refs: []
case_ids: [AC-09, AC-10, AC-11, AC-59]
evidence: []
unverified: [真实持久化, 真实运行消费, 重启恢复]
```

执行者产出功能和记录；验证者直接读取产物及原始结果。没有独立人员/模型时，使用与实现总结分开的确定性检查及真实业务回读。政策检查负责确认测试范围和副作用授权，不替代功能验证。长期记忆/Skill不是产品验收的必需产物，本次不写入长期记忆或升级技能。
