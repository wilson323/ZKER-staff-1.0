## 4. 低学习成本的完整交互

以下是待实现、待可用性测试的交互规格，不是现成产品运行结论。

### 4.1 任务内 AI 帮我设置

从统一待办打开任务，顶部保留事项单号、流程版本、节点、本人职责、截止时间及正式交付状态。主区显示交付目标和当前缺口；AI提供“按当前要求准备”主操作。员工已经具备默认方案时直接看到预览，不再被要求挑选模型、技能标识、编排方式和知识切块策略。

预填优先顺序：组织允许范围 → 当前模板版本 → 本任务上下文 → 本人显式偏好 → 经验证的适用样例。低优先级不得覆盖高优先级禁令。AI只为确实缺失的信息提问，例如“本次报告覆盖哪些区域”，不重复询问已在任务记录中的时间和负责人。选择理由可展开查看。

配置预览只呈现四件事：“帮我做什么”“依据什么”“准备什么交付”“哪些动作要我处理”。下方给预计资源消耗的区间或未知状态，不展示无依据的精确预测。高级设置保留全部能力，但在有权限且需要时展开。

采用前显示差异：字段、旧值、新值、建议来源、影响对象、是否改变授权。用户改写后重新校验；保存时校验原配置版本，遇到冲突保留草稿并重新比较。保存成功的文案不能写成“任务已完成”。缺少连接时显示“还需连接此数据源”，可继续人工处理或生成不依赖该源的草稿，不能默认有数据。

### 4.2 AI 数据分析

工作台或主管视图允许问“本周哪些流程最容易逾期”。系统先展示可读的分析计划：统计对象是人员任务还是去重业务实例；按开始时间还是到期时间选取；业务时区与区间；关闭/撤销事项是否排除；实际可见组织与字段；数据更新时间。歧义会显著改变结果时先让人选口径。

后台必须使用真实只读连接或受限查询服务，复用原身份、行列权限和查询限额，校验查询结构、可用字段、扫描范围及超时。只写提示词“不要修改”不构成只读保证。重复查询复用明确快照，权限撤销时缓存也必须失效。

结果卡包含结论、数据表/图、口径版本、来源与时间、限制，允许展开查询计划/执行标识并下钻可见原始事项。没有样本、权限不足、查询超时和结果为零是四种不同状态。相关性只表述为线索；归因需进一步证据。生成“建议处理清单”是草稿，不能直接批量改任务、指派人员或形成个人绩效结论。

### 4.3 业务本体知识库

首期先复用已有业务对象：组织/人员/角色、流程模板版本、业务实例、人员任务、数字员工版本及绑定、上下文快照、交付物版本、人员决定、知识来源和指标口径。按现有ID连接“负责/协作/审核”“属于实例”“基于资料”“由运行生成”“取代版本”等关系，不复制第二份可写业务主表。

每条派生事实保存来源ID与版本、定位、有效时间、提取/确认方式、确认人和可见范围。图中推断出的关系标为候选；没有人员确认的抽取不能改负责人、审核链、权限或正式业务口径。索引和图视图服从源系统权限，恢复索引时可按来源重建。

普通员工看“本任务相关资料”“这个结论的依据”“上下游受影响对象”。知识维护者才看映射、冲突、失效和版本差异。页签可以展示关系图，但不以编辑大图谱作为完成日常任务的前提。来源冲突时并列展示及请求口径负责人处理；向量相似度不得伪装成真实性概率。

### 4.4 主动建议与有限自主执行

触发可来自任务到期、交付缺项、上下文变更、依赖完成、明确订阅的业务事件或周期。每张卡必须包含触发事实及版本、生成时间、当前适用范围、优先级原因、建议动作和预期产物。组合键可采用 `tenant + user + workItem + ruleVersion + sourceEvent` 去重；相同问题被忽略后进入可配置冷却，源事实有重要变化才重新提示。

默认行为是准备方案或草稿。用户可对明确动作授予有限授权：对象范围、允许读写动作、期限/次数、预算、外部目标、必须停下的条件。启动前及副作用前均重新校验权限、任务状态和来源版本。确认外发时显示接收对象、内容版本和影响，不能把“信任AI”作为无边界总开关。

界面区分“暂停后续提醒”“暂停新触发”“停止当前运行”；停止后检查已发生副作用并给出补偿方案。重复事件、超时或网络断开先查询执行回执，不能无依据重发。OA节点完成、审核签署和正式交接仍由当前有权人员决定。

### 4.5 受控记忆与自主进化

记忆保存稳定偏好与经确认规则；知识保存可引用材料；任务上下文保存当前事实快照；审计保存发生过的行为。四者不因“AI能学习”而合并。员工可以查看来源和生效范围、纠错、停用或回到先前版本；私人反馈不自动公开给协作人或市场。

进化入口放在员工详情的“改进建议”。每份提案说明问题、真实验收记录、影响版本、改动差异、预期改善及潜在退化。离线评估使用经授权的已脱敏案例，固定基线、候选、模型/工具版本及评分口径；至少覆盖正常、错误、越权、版本冲突和恢复案例。语法通过只是第一层，业务验收与权限不可退化才可进入限定用户/任务的试用。

试用可停止；发布记录审核人、适用范围、版本和回退点。低风险草稿优化可以在已有有限授权内自动推进评估；发布组织公共技能、改变正式流程和任何安全/权限策略仍须既有治理。回退只改变今后生效版本，不删除旧审计，不假装撤回已经外发的产物。没有真实评估证据时显示“提案待验证”，不使用“已变聪明”“效果提升”等文案。

| 指标 | 计算/记录方式 | 建议验收目标 |
|---|---|---|
| 找到本人下一步 | 从工作台开始到打开正确人员任务，记录时间及错误进入次数 | 首次中位数≤30秒；不误入同流程其他实例 |
| 首次可运行配置时间 | 从打开任务到通过资格与配置校验，不把等待模型计入人工设置时长 | 已具备默认资源场景中位数≤2分钟；缺凭据单独统计 |
| 决策负担 | 首次运行前必须人工决定的字段数，另记高级设置打开率 | 常见模板首屏必答≤3项；不减少责任与授权信息 |
| 正确完成率 | 无主持人帮助完成指定任务且提交正确版本的人数/参与人数 | 预设任务达到≥90%；必须同时报告样本量 |
| 责任理解 | 让参与者指出谁负责、谁审核、AI能否提交正式交付 | 关键责任问题全部正确；发现误解即修订文案 |
| 纠错与回退 | 故意给一条错误建议，记录发现、修正、保留旧值的路径 | 两次交互内能打开差异或撤销入口；实际回退再单测 |
| 分析可复核率 | 抽取答案，核对口径、时间、来源和明细是否支持结论 | 有效答案100%有依据链；缺依据时显示不可确认 |
| 主动提醒有效性 | 记录采取有效行动、忽略、重复提醒、误触发及中断次数 | 先测基线；阈值由试用确定，不预报“提升百分比” |
| 配置/版本错误 | 同时统计错误对象、陈旧版本、误授权及错误覆盖 | 越权与错误正式交付为0；非零即不通过 |

不使用点击越多、聊天越长、建议采纳越多来单独衡量AI价值。主动拒绝错误建议和选择人工处理也可能是正确结果。

## 7. 断点、风险和恢复

| 断点 | 用户看到的状态 | 恢复与验收要求 |
|---|---|---|
| 没有模型或连接权限 | 尚未就绪、具体缺项与可继续的人工路径 | 配置者补齐后做最小真实任务验证，不把“已保存”当“可运行” |
| 上下文/配置被并发修改 | 本地草稿保留，旧版与新版差异 | 重新获取快照并确认；禁止覆盖别人修改 |
| AI猜错对象或口径 | 显示所选实例/粒度/时间，可撤回选择 | 改口径重查；旧分析标注失效 |
| 知识解析失败或来源冲突 | 区分处理失败、可见但未就绪、事实冲突 | 修正原资料、重新处理并用已知/未知问题验收 |
| 权限运行中撤销 | 执行停止或拒绝下一动作，已发生动作可查看 | 清理可见缓存，保留受保护审计；重新授权也不自动续跑 |
| API已接受但没有产物 | 执行中/失败/部分完成及最后可靠检查点 | 对照回执与产物核实，有限重试，避免重复修改 |
| 提醒风暴 | 合并为摘要并支持暂停与关闭规则 | 修复触发/去重，回放同一事件确保幂等 |
| 进化只通过结构检查 | 提案待业务验证 | 加入冻结验收案例与基线对比，不能直接宣称提升 |
| 发布后退化 | 试用停止/版本回退，受影响任务可筛选 | 恢复已确认版本；单独补偿已产生的外部影响 |
| 前端展示缺失状态或误导成功 | 保留操作输入并给可重试入口 | 校验真实响应、授权、版本及产物，不能只靠绿色提示 |
