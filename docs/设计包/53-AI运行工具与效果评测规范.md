# AI运行、工具与效果评测规范

开发文档包0.1｜`AI_DESIGN / MODEL_EVALUATIONS_NOT_RUN`。本文件细化41与35；全产品融合AI，人员责任、低代码配置和统一权限保持不变。产品AI与帮助开发的AI编码Agent分别评测。

## 1. 唯一运行链与权限边界

```mermaid
flowchart LR
  U[人员意图与本人任务] --> B[Binding精确版本]
  B --> P[当前权限/来源/预算校验]
  P --> S[ExecutionSnapshot]
  S --> SDK[底座唯一Agent SDK循环]
  SDK --> T[工具网关:动作/目的地/Grant/fence]
  T --> C[候选产物与真实回执]
  C --> O[按受众检查OutputRelease]
  O --> V[人员工作台获准投影]
  V --> H[独立审核/人员确认/正式交付]
```

低代码流程/Agent方案只配置已注册步骤和输入输出Schema。OA定义人与交付路径，节点内方案定义本人的数字员工任务；不得用AI图重做OA审批，也不得让插件自带第二层无限Agent循环。模型Provider、工具、检索器和计划节点通过底座已有扩展点接入。

## 2. 每次执行的必需合同

| 项 | 规范 |
|---|---|
| 触发 | work/当前humanTask/epoch、操作幂等键、明确用户意图或有效有界计划 |
| 输入 | Binding版本、Baseline、Manifest、精确资源引用、schemaVersion、purpose |
| 授权 | 执行主体、来源用权、字段、动作、模型/工具目的地、期限、当前policy/authz版本 |
| 输出 | 输出Schema、候选ArtifactVersion、来源引用、结果发布策略；不以自由文本“完成”作回执 |
| 限额 | token、工具次数、时长、最大并发、成本/结算范围；以组织上限为界 |
| 状态 | Attempt、SDK run/checkpoint、fence、operationId、实际Invocation回执 |
| 停止 | 达到目标、预算耗尽、无进展、需人输入、授权失效、工具效果未知、取消确认 |
| 恢复 | SDK真实支持的检查点+相同输入版本；未知外部效果先查证；不支持则明确新Attempt |

示例设计默认：一次任务最多20次工具调用、120秒执行时长、20000 token；实际采用时按模型和业务测量调整且不得超过Schema/组织限额。这些是建议预算，不是已实现性能承诺。重复失败没有新信息最多2次有依据修复；外部写不能按通用重试策略重发。预算计量按Invocation/usage事件去重，避免模型重放重复计费。

## 3. 工具与插件接入

工具使用48号插件清单和输入输出Schema；清单中的风险/只读注解只能作为线索。平台解析精确provider/action版本，再从原连接身份、当前任务Grant和目的地范围判断是否可调用。MCP/OpenAPI只是接入协议，不增加业务权限。

| 动作类别 | 默认方式 | 失败处理 |
|---|---|---|
| 获准只读检索/分析 | 自动执行当前任务范围 | 有限退避；无权限/失效不换身份绕过 |
| 本地可逆候选配置/文档 | 生成草案并展示差异，用户可采用 | 保留草稿和来源，不假装已发布 |
| 实际外发/写业务系统 | 原任务明确授权、当前作用域与真实回执 | 超时UNKNOWN，查证幂等业务键 |
| 权限、发布、删除、生产等敏感动作 | 走原领域命令与相应有权人员确认 | 插件不能自批或扩大授予范围 |

工具输出是不可信数据；它可以包含提示注入，不能改变系统权限、目标或授权。模型看不到的敏感工具返回由后台受限处理器保存引用，不原样放进可被复制到用户对话的上下文。日志默认记录事件/摘要/错误码和受控引用。

## 4. 上下文、知识、本体与记忆

最新具体存储、工作区与检索设计见[56号](56-知识记忆技术栈与实施决策.md)，选型依据及许可见[55号](55-知识库与记忆开源方案深度研究.md)。项目文档、任务输入/草稿/交付、主题知识与长期记忆有不同生命周期；以来源对象和版本关联。短期ChatMemoryStore窗口须真实持久化，但窗口淘汰不删除业务历史。人员对话与获准后台执行使用不同上下文和记忆作用域，受限原文不得先进入人员模型再靠提示词隐瞒。

上下文构造顺序：当前目标/输出合同→已确认共同事实→当前责任允许来源→本任务近期获准历史摘要→任务需要的工具说明。检索先按源和用途授权过滤，rerank后仍保留来源版本；运行或发布前再验，不能检索后才从结果文本中删秘密。

本体关系是带来源的业务断言：subject/predicate/object、sourceRefs、有效期、范围、状态。候选关系不能自动变成事实；冲突呈DISPUTED，由有权人员确认。遍历每条边和端点都需源权限，不能靠图的邻居数量泄漏隐藏关系。

个人、Agent、任务、团队、组织记忆分域，复用底座记忆能力；保存“有用内容”不自动发布到共享知识。来源撤权/过期/删除影响引用、索引、关系和生成摘要；先停止访问，再异步更新索引。总结、长期记忆和经验发布均可追溯到原始来源及版本，不把模型自信当验证。

## 5. 分析与设置AI

分析先生成AnalysisPlan：问题、指标版本、粒度、时间字段、范围/时区、过滤条件、授权来源、快照水位、限制。只能运行受控指标查询或只读数据服务，禁止模型直接提交任意SQL。结果保存为类型化AnalysisResult和必要ArtifactVersion，图表、表格和下钻共用结果版本。

`sampleCount=0`时指标为null/NO_DATA；有样本且业务值为零时为0。查询失败/权限不足分别返回错误，不返回假0。来源和口径变更使旧结果STALE，重新查询前不展示旧图为最新。自然语言解释必须引用实际数字/单位/时间窗，不能添加没有数据支持的趋势或因果。

设置AI只提出白名单字段差异，作用域限CURRENT_WORK或PERSONAL_PREFERENCE。单项采用仍检查组合约束，撤销使用原mutationId和当前revision；有新修改则冲突。权限、角色、tenant、出站策略、密钥与核心审核要求不在建议可写字段中。员工默认无需配置模型温度、prompt拼接和检索算法。

## 6. 主动AI及自主进化

主动建议来源必须是已授权真实事件，包含去重键、接收者、关联工作、理由、有效期和冷却。默认生成一张机会卡，接受后进入原工作草稿/既有计划；不会因为有建议就新开执行循环。自动运行只在事先明确有界授权下，由原调度器触发，每次重验身份、源版本、预算、期限和并发；过期/重复/静默期事件不启动。

进化只修改可复用配置、技能、提示词/检索/工具选择等候选能力，不能修改核心权限、审批、生产访问或敏感数据规则。必须固定baseline/candidate/testSet/model/tool/policy的精确版本与摘要。

| 对象 | 状态与出口 |
|---|---|
| 配置提案 | PROPOSED→APPLIED或DISMISSED/EXPIRED/STALE；撤销产生新变更，不抹历史 |
| 知识加工 | QUEUED→PROCESSING→READY或FAILED；READY还不代表当前人可读 |
| 分析 | PLANNED→RUNNING→SUCCEEDED/NO_DATA/FAILED；版本变化STALE |
| 关系断言 | PROPOSED→CONFIRMED或DISPUTED；源变SUPERSEDED/REVOKED |
| 主动机会 | PENDING→ACCEPTED/DISMISSED/SNOOZED/EXPIRED/INVALIDATED |
| 进化提案 | PROPOSED→EVALUATING→EVALUATED→REVIEW_REQUIRED→TRIALING→PUBLISHED；失败REJECTED，变更STALE，回退ROLLED_BACK |
| 插件版本 | DRAFT→VALIDATED→ENABLED→DISABLED/RETIRED；有历史/运行依赖时保留版本 |

试用限定成员/业务范围/时间/预算和停止阈值。发布只更新未来默认版本，运行任务固定版本；紧急安全撤权立即生效。回退恢复未来默认，不撤销已经发生的邮件、付款或业务写操作；外部效果需独立补偿。

## 7. 产品AI评测样本与判定

Agent内核新增研究及性能设计见[57号](57-Agent运行框架最新源码研究.md)/[58号](58-Agent技术架构与性能实施设计.md)。AR-P01—AR-P30均NOT_RUN，覆盖启动重复、会话隔离、沙箱失败、精准批准、未知效果、跨副本恢复、取消清队列、SSE背压、父子预算、正式交付及制品准入。候选按60号先做能力差额筛选，仅一个挑战者与合格基线进行POC，固定模型、工具、权限、数据及冷/热启动条件；性能分别记录排队、模型、工具、首个获准反馈、产物就绪、人工修订、RSS和用量，不用语言/Star/代码行数推断快慢。

新增专项测试计划为56号KM-P01—KM-P30，全部`NOT_RUN`。覆盖同员工多主体、多实例工作区、撤权与缓存、源版本失败、精确/混合/文档树检索、中文扫描表格、记忆并发/纠错/恢复、候选进化、文件越界和整包许可。采用相同材料/模型/权限/预算比较目录全文、Qdrant、Docling与有限文档树方案，记录质量、成本、延迟及人工修订时间；它们是既有AI/EW及原知识需求的细化，不替换原AC或冒充已建立测试集。

[ai-evals.json](../../contracts/fixtures/ai-evals.json)包含16个具体场景，均为`NOT_RUN`：配置推荐/撤销、RAG泄漏与撤权、本体冲突、分析真零/无样本/注入、主动去重/失效、进化未评估/版本漂移、工具未知、预算与首次任务体验。输入、预期、判定方法和关联需求完整保留。

| 指标 | 计算方式 | 采用门槛 |
|---|---|---|
| 权限泄漏/越权/重复副作用 | 真实响应、工具账本、哨兵与语义审查 | 任一出现即失败，不能被平均分抵消 |
| 结构正确 | 结果符合版本Schema及跨字段业务约束 | 适用样本100%；只是最低门槛 |
| 业务成功 | 实际文件/数据/回执符合任务合同并完成人员验收 | 按任务族统计；未测/空测试集不得通过 |
| 引用与数字正确 | 引用版本真实存在可读；数字对照确定性数据 | 数字/单位/范围零错误；无依据断言不能发布 |
| 体验负担 | 成功完成任务所需动作、首次成功率、返工原因 | 与相同任务基线对照，不凭主观“更智能” |
| 成本/延迟 | 同条件token、工具数、耗时和真实结算 | 不超授权预算；收益不足不发布 |

正式基线每个主要任务族至少30个有代表性场景，随机型模型至少重复3次并保留失败；这是初始评测计划，不是统计充分性保证。高风险稀有样本单列，训练/改进样本和留出集隔离。初始16例用于发现断点，不足以宣称全业务可靠率。报告必须写样本量、模型/工具/策略版本、预算、成功定义、原始证据和不确定性。

## 8. AI编程评测与发布边界

帮助开发的AIAgent仍沿用本项目开发体系、currentTask和REVIEW。其评测看是否读对仓库、是否维护合同、是否运行实际检查、是否伪造成功、是否越权/串项目，不用产品AI问答准确率替代。已有工程工具回归和隔离Agent试验按自身报告范围解释，不能推导本产品AI已运行。

真实模型/插件/检索器改变后，先固定当前基线，在隔离范围试用并比较，独立核对证据后才决定采用。未通过或无证据时保留草案；普通用户不会被迫学习评测配置，维护者在资源详情查看版本差异和证据即可。
