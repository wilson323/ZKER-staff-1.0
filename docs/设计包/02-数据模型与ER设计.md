# 数据模型与 E-R 设计

本文件提供逻辑模型、存储约束和增量字段设计。标记 **E** 的对象已经在当前领域文档/合同出现；不代表其全部读写链已实现。标记 **N** 的对象是本次新增候选合同；字段和表名不得直接视为现有数据库。实际迁移需要先核对当时 Alembic head、外键类型及消费者。

## 1. 领域边界与事实归属

| 子域 | 权威对象 | 可派生的视图 | 禁止重复维护 |
|---|---|---|---|
| 组织与身份 | Tenant、User、TenantMembership、HumanTask、Delegation | 本人任务、参与者姓名、岗位来源 | 第二套 tenant 来源、第二个人员当前责任字段 |
| 流程 | SOPVersion、NodeContract、ProcessInstance、WorkExecution、WorkItem | 业务进度、下一接收岗位 | 前端自己推进节点或复制流程终态 |
| 分配与运行 | CandidateSnapshot、AgentAssignment、ExecutionSnapshot、ExecutionAttempt | 当前数字员工、运行状态和配置摘要 | 同一 WorkItem 多个 active Assignment |
| 能力资产 | AgentProfile、AgentDefinitionVersion、Capability/Skill/Knowledge 版本及 Grant | 我的/共享/推荐目录 | 把资源目录可见当作运行授权 |
| 协作事实 | WorkThread、WorkThreadEntry、N CollaborationLink、N Contribution | 分工列表、待合并贡献、事实基线 | 将聊天摘要作为独立可改写业务真相 |
| 授权上下文 | ContextManifest、N ExecutionContextBinding、N ContextApplication | 上下文就绪程度与已应用版本 | 共享私人 prompt、共享权限票据 |
| 交付与证据 | CompletionCheckResult、ResultCommit、HandoffPackage、Artifact、Evidence | 完成卡、交接预览、证据时间线 | 将 Runtime success 或“已读”改写为业务完成 |

### 3.1 CollaborationLink：把合法协作工作接到主任务

建议物理名 collaboration_links；新表候选。**不存可独立修改的 assignee**，实际承担人从子工作项 HumanTask 查询。

| 字段 | 类型/必填 | 约束与用途 |
|---|---|---|
| collaborationLinkId | PublicId / 是 | 稳定主键，存储层适配现有 UUID |
| tenantId | PublicId / 是 | 从 Cookie 会话和服务端上下文取得 |
| parentWorkItemId / childWorkItemId | PublicId / 是 | 同租户；不得相同；子项最多一个主协作父项 |
| collaborationRequestRef | PublicId / 是 | 回到请求事实与 IntentDecision 来源 |
| objective | 非空文本 / 是 | 这份分工具体完成什么 |
| expectedOutputSchemaRef | 版本化引用 / 是 | 用于子任务输出与贡献校验 |
| baselineWorkItemRevision | 正整数 / 是 | 接受请求时引用的主工作业务版本 |
| requiredForParent | boolean / 是 | 是否是父任务已有合同允许的必需贡献 |
| delegationRef | PublicId / 否 | 需要代办动作时引用有界 Delegation；不是凭本字段授权 |
| dueAt | timestamptz / 否 | 不得越过合同上界；时区存 UTC、展示用户时区 |
| status | enum / 是 | requested / accepted / declined / active / delivered / closed / cancelled |
| revision | 正整数 / 是 | CAS 并发控制 |
| createdByMembershipId / createdAt | PublicId / timestamptz / 是 | 审计来源 |

requested 可先没有可执行子工作项，如何避免空外键：创建协作请求时复用请求事实；**正式 CollaborationLink 在子 WorkItem 建立时落盘**，初态 accepted 或合法预授权下 active。requested/declined 是请求视图状态，不创建带空 childWorkItemId 的“半张表”。Schema 中存储态只允许 accepted/active/delivered/closed/cancelled。主界面聚合请求记录与 Link，不能把二者各算一次。

D-01 推荐建立独立 AD_HOC 子 WorkExecution，其 IntentDecision 和业务资源与协作请求关联。静态流程职责仍建成 SOP 节点。requiredForParent 只能来自既有节点完成合同或经授权的合同变更；主执行人不能无权新增阻断整个流程的审批或必需门。

### 3.2 Contribution：专业贡献与接受记录

建议物理名 work_contributions；新表候选，内容版本不可变，状态变化写现有审计/有序事件。

| 字段 | 类型/必填 | 约束与用途 |
|---|---|---|
| contributionId / tenantId | PublicId / 是 | 联合租户边界 |
| collaborationLinkId / childWorkItemId | PublicId / 是 | 子工作与关联必须相符 |
| contributionVersion | 正整数 / 是 | 同 Link 单调递增；不覆盖旧内容 |
| basedOnContextBindingId | PublicId / 是 | 可追到授权投影和基线 |
| basedOnParentRevision | 正整数 / 是 | 提交时校验仍适用于当前业务 |
| artifactRefs | VersionedRef[] / 是 | 至少一个可解析产物；每项 ref/version/digest |
| structuredResultRef / resultDigest | 引用 / 摘要 / 是 | 结构化结果与证据绑定 |
| completionCheckResultId | PublicId / 条件 | submitted 及以后必须有有效检查结果 |
| status | enum / 是 | draft / submitted / accepted / returned / needs_recheck / superseded / withdrawn |
| submittedByMembershipId / submittedAt | 条件必填 | submitted 后必填；由子任务责任人确认 |
| decisionByMembershipId / decisionAt / reason | 条件必填 | 接受、退回、撤回、替代须可追溯理由 |
| revision | 正整数 / 是 | 防止并发接受/退回 |

接受贡献不自动改变父节点终态。正式输入发生影响变化时 accepted → needs_recheck；通过新上下文及检查形成新贡献版本后旧版 superseded。已使用的历史交接包仍引用旧版事实，不能随状态变化改写已交接内容。

### 3.3 ExecutionContextBinding：冻结“这一轮到底基于什么”

建议物理名 execution_context_bindings；新候选绑定记录。复用现有 ContextManifest 和 ExecutionSnapshot，不向 additionalProperties:false 的现有 Schema 偷加字段。

| 字段 | 类型/必填 | 约束与用途 |
|---|---|---|
| contextBindingId / tenantId | PublicId / 是 | 不可变绑定 |
| workItemId / workItemRevision | PublicId / 正整数 / 是 | 本次工作及版本 |
| assignmentId / attemptId / executionSnapshotId | PublicId / 是 | 同租户、工作项和当前分配关系相符 |
| contextManifestId / contextManifestDigest | PublicId / Digest / 是 | 目标主体、用途和有效期 |
| baseThreadSequence | 非负整数 / 是 | 基线所涵盖的授权业务事实水位；不是全部线程读取许可 |
| sourceRefs | VersionedRef[] / 是 | ref、version、digest、required、purpose；为空仅限无前置资料任务 |
| sourceRefsDigest / inputDigest | Digest / 是 | 源集合和业务输入确定性摘要 |
| requiredFactKeys | string[] / 是 | 必须保留的目标、约束与完成条件键 |
| policyRevision / authzEpoch / expiresAt | string / 非负整数 / 时间 / 是 | 仍需使用时重授权，不能凭快照长期通行 |
| pluginProfileDigest | Digest / 条件 | Agent 执行涉及插件配置时必填，来源于既有配置解析 |
| bindingDigest / createdAt | Digest / 时间 / 是 | 绑定字段的规范化摘要与创建时间 |

bindingDigest 不含自身字段。摘要算法在正式合同冻结时统一规范化序列化；不能把字段顺序不同导致的 hash 当作业务变更。sourceRefsDigest 必须对应同一规范化引用集合，且与关联 Manifest 相符。executionSnapshot 中已有 AgentDefinitionVersion、runtimeProfileVersion、能力版本和策略；新绑定通过引用复用这些字段，不各维护一份独立值。

纯人工执行不得伪造 Agent 装载记录：人类 ContextManifest 的阅读/接收记录复用 NotificationDelivery 和 WorkThread 决定；本对象针对已有 Assignment/Attempt 的运行输入。若人工工作现有合同无需 Attempt，使用上述人类路径即可。

### 3.4 ContextApplication：记录投递与装载证据

建议优先复用现有 Runtime 事件/投递事件形成读模型；只有现有持久事实无法支撑时才新增同名表。本候选 Schema 定义读取与验收语义，不强制新建事件总线。

| 字段 | 类型/必填 | 约束与用途 |
|---|---|---|
| applicationId / tenantId / contextBindingId | PublicId / 是 | 绑定精确上下文 |
| attemptId / consumerSubjectId | PublicId / 是 | 运行消费者身份 |
| state | enum / 是 | prepared / delivered / loaded / update_required / blocked / revoked |
| deliveredAt / loadedAt | 时间 / 条件 | 无可验证证据不能填 loadedAt |
| appliedSequence | 非负整数 / 是 | 已装载并可验证的业务事实水位 |
| observedSequence | 非负整数 / 是 | 已观察到的可见变更水位，不等于已应用 |
| evidenceRefs | PublicId[] / 是 | 事件、装载证明、受控行为检查来源 |
| blockedReasonCode | string / 条件 | blocked 或 revoked 时解释原因 |
| revision / updatedAt | 正整数 / 时间 / 是 | 读模型更新依据与恢复 |

loaded 表示有契约约定的装载证据，不表示模型在所有情况下完全理解。理解质量通过公开目标/约束摘要、来源和独立业务检查评估，不保存模型内部思维过程。现有 Adapter 仅写 prior-context.json 的行为不能签发 loaded。

## 4. 扩展域模型与资源关系

| 领域 | 复用对象/视图 | 必须保留的业务字段 | 关系与约束 |
|---|---|---|---|
| 数字员工 | AgentProfile + DefinitionVersion | 名称、职责、风格、边界、发布版本、维护者、可见关系 | Profile 1:N Version；Assignment 固定版本 |
| 技能/方案 | SkillCard/SkillVersion + CapabilityManifest | 输入输出 schema、参数、依赖、阶段、失败策略、测试来源 | 已发布版本不可变；选择器查询 eligible 集合 |
| 连接器 | Tool/MCP + Grant + ConnectionIdentity | 应用动作、调用身份、范围、授权到期、健康、版本 | “已接入/已授权/已授予/节点可用”分别来源 |
| 知识 | KnowledgeBase/Source/Version/Citation | 解析状态、发布状态、原文版本、片段、权限 | Citation 读原文时重鉴权 |
| 记忆 | 既有 Memory/经验提案 | 主体范围、来源、有效期、适用任务、修订、发布范围 | 私人→团队须显式发布；不能复制私人权限 |
| 文件 | 既有 Artifact/对象存储版本 | 对象键、版本、摘要、媒体类型、分类、归属、来源 Attempt | 不能只用本机绝对路径作为跨人交付地址 |
| 团队 | 既有 Team/成员授权与 Runtime 内部分工 | 协调者、成员能力、上限、输出汇总规则 | 一个人的多 Agent 团队不产生多个人类责任 |
| 自动化 | Schedule/触发配置 + Run | 时区、规则、去重键、截止、重试、并发、任务目标 | 触发配置不携带长期通行授权 |
| 渠道 | Channel + Membership 映射 | 外部会话与线程关联、消息ID、身份、路由、投递状态 | IM→Web 同一工作项，消息去重 |
| 组织/IAM | Membership/Employment/RoleBinding/Grant | 任职、有效期、动作范围、来源、撤销状态 | 任职不等于授权；Cookie 为 HTTP tenant 来源 |
| 用量/审计 | UsageRecord/Trace/Audit/Notification | 业务关联、动作、结果、时间、单位、cost source | 原始用量不可用前端估算覆盖 |

此表是开发需要的字段需求，不保证当前每个对象都有同名物理列。存量 Schema 字段字典由本包证据导出记录；正式增量只合并缺失字段，不能依表批量另建同义资源库。

## 5. 公共类型、索引与一致性

- PublicId：遵循现有 API ID 模式；数据库 FK 使用当前实际类型，不混用公开 ID 与 Runtime Session 内部标识。
- Digest：候选合同统一 sha256: + 64 位小写十六进制；接入当前无前缀摘要字段时做显式边界适配，不能混存比较。
- VersionedRef：ref、version、digest、required、purpose；引用解析必须校验租户、目标读权、版本存在和摘要。
- 所有跨表 FK 必须带 tenant_id 或等效可证实的租户一致性约束；事务锁查询同时限定租户。
- collaboration_links：unique(tenant_id, child_work_item_id)，索引(tenant_id,parent_work_item_id,status)；防自指和循环需事务级祖先检查。
- work_contributions：unique(tenant_id,collaboration_link_id,contribution_version)，索引(tenant_id,collaboration_link_id,status)。
- execution_context_bindings：unique(tenant_id,attempt_id)，关联 snapshot/assignment 的组合约束；新上下文需要新 Attempt 或现有 Runtime 明确支持的重绑定合同。
- ContextApplication 投影视图按(binding,consumer)定位，appliedSequence/observedSequence 单调且前者不大于后者。
- WorkThreadEntry 延续 unique(thread,sequence) 设计及不可变事实，不以 createdAt 作为跨服务全局排序。
- 引用链校验失败、版本冲突、缺必需资料、无权/不存在必须区分业务原因，但对象存在性仍按既有隐藏规则处理。

## 6. 事务边界、保留与迁移方案

T1 接受协作：校验请求/成员/作用域 → 既有 AD_HOC 创建语义 → HumanTask 与 CollaborationLink → Outbox；同一幂等请求只生成一个子项。没有合法 AD_HOC 输入时拒绝，不造空壳数据。

T2 冻结执行：CAS 工作项/Assignment → 有效配置与 Manifest → ContextBinding → Attempt/Envelope；Manifest 及绑定不授予新权限。

T3 接受贡献：锁定主项 revision、Link 和贡献 → 检查基线/权限/必要检查 → 记录接受决定和有序事件。是否推进父任务由独立 ResultCommit 决定。

T4 正式提交：沿既有 ResultCommit 事务边界保存完成事实、证据、不可变交接和 Outbox；实际远端动作不并入数据库事务，使用回执与补偿。不能宣称跨服务 exactly-once；以幂等消费和对账实现单一业务效果。

迁移顺序：盘点同义列/表 → 合同和消费者 → 添加可空引用或增量表 → 有明确依据的数据回填 → 完整性检查 → 启用约束与读路径 → 最后启用写入口。无法从旧数据还原的上下文一律标 legacy_unverified，不能伪造 loaded。回退关闭新增入口并保留审计；不删除已发生贡献，不改旧包摘要。

物理 DDL 需要当前 Alembic head 下生成、测试和审批后才执行。本包交付模型与候选 Schema，不执行数据库迁移。

ResourceVersion是AgentDefinitionVersion/SkillVersion/Tool版本的逻辑联合，不要求新增同名表。LocalCopy记录源Publication、类型、源版本/摘要、目标个人资源ID、创建人、采用意图与Lineage；目标使用Grant和连接身份必须重新从接收方现有权限解析。来源更新不改在途ExecutionSnapshot。

MarketResourceCard读取名称/用途/版本/依赖/allowedActions及当前主体可用性；MarketAdoptionResult读取采用操作、个人副本、来源、就绪和节点资格。结构候选见13-市场采用候选.schema.json；跨对象授权、幂等和类型策略由服务端校验。具体字段与流程见 [员工市场复制与使用设计](<12-员工市场复制与使用设计.md>)。

## 11. OA多实例与队列模型补充（v2.5）

本文件原有 `SOPVersion → ProcessInstance → WorkExecution → WorkItem → HumanTask` 一对多链是多笔事务基础，不能在UI中收缩成一个人一个流程。新增逻辑ER、业务号/来源单据关联、InboxEntry只读投影、草稿/阅读态候选及索引事务约束见OA补充设计第4节。草稿键包含租户、成员、workItem和轮次；同一人的两个任务不共用可变配置、会话或执行空间。ProcessInstance与WorkExecution沿既有关系，不增加第二套业务实例终态。
