# 模块边界与前端工程设计

技术设计1.0｜2026-09-11｜`PROPOSED / NOT_IMPLEMENTED`。依赖[37号总设计](37-技术架构总设计与决策.md)，保持[31号原型](31-完整产品交互原型.html)的产品交互，不直接把原型内存脚本当生产代码。

## 1. 模块划分与依赖方向

以芋道作为条件性目录映射，新增一个`yudao-module-collaboration`业务模块，内部按package分领域，初期不拆成独立微服务。名称为拟议工程结构，不表示已选定底座或本项目已有源码；验证优先级与改选规则见37号2.2。若改选，在最终底座等价模块中保留这些业务边界，不能混装两套引擎与SDK循环。

```text
yudao-server                         组合已有模块与应用API
yudao-module-system                 人员、组织、既有会话及角色
yudao-module-infra                  文件、通知、任务调度等成熟基础
yudao-module-bpm                    引擎适配、人工任务和流程办理
yudao-module-ai                     模型/角色/工具/知识等既有资产
yudao-module-collaboration
  work                             工作目标、责任、任务绑定
  context                          来源版本、快照、人员展示投影
  contribution                     分工、贡献、审核与交接
  adoption                         市场采用、个人副本与谱系
  execution                        Attempt/ToolEffect/预算与恢复服务
  intelligence                     分析口径、关系断言、主动机会、进化提案
  integration                      BPM、AI、工具、事件适配接口
  controller / service / dal        遵循底座已有分层
oa-ai-worker                       独立运行配置/进程，复用同一AI库
web/src/views/work / resources      统一员工与资源页面
```

controller只做协议、校验和可信主体提取；service负责授权、版本守卫及事务；DAL不接受未校验的租户字符串；适配器调用底座公开服务。内部事件用不可变最小引用，禁止跨package随意写他人的表。BPM生命周期仍由bpm办理，不能让Worker直接complete人工任务。ai模块不反向依赖员工前端或浏览器角色。

专用Worker可以领取队列表租约；业务正文与凭据只能通过受控内部API或专用数据访问层按ExecutionGrant取得，不向Worker发全库账号。相同SDK和资源版本只生成一次执行循环；团队成员是在同一Attempt树下的子执行，不另建OA节点状态。

## 4. 工作台组件与交互状态

`WorkShell`持有taskRef、processRef、responsibilityEpoch与授权投影；左侧`TaskConversation`，右侧`WorkDisplay`含`ExecutionPathView`、`ArtifactPreview`、`ArtifactFolder`、`ConversationSummary`。鱼骨图是后端已授权的节点/边只读投影，复用Vue组件+SVG即可；流程编辑仍使用底座同一BPMN/简易模型。首次不为路径图另引入第二个流程编辑器。

共享选中状态只有`taskId、nodeId、artifactRef/version、displayTab`。公开URL不放原文、搜索词、凭据、受限文件名；跨人或撤权清掉展示状态，参数不构成授权。390px切换对话/展示而不是缩小整张桌面图，键盘能遍历节点、切换Tab、打开引用并返回焦点。状态以文字/图标共同表达，不能只靠颜色。

状态分为：server snapshot（权威读模型）、query cache（可丢弃）、view state（当前定位）、draft（本人未发送输入）。服务端草稿是长期事实；浏览器仅保存会话期草稿，敏感正文默认不落localStorage/IndexedDB。用户明确需要离线编辑时另行设计加密、撤权和保留策略，不能默认缓存完整任务。

所有查询key包含subject、tenant、work、epoch和policyRevision。切换时递增requestGeneration并abort旧请求；响应到达同时核验当前generation与投影版本，不能只依赖取消网络。SSE重连只恢复观察，不再次开始Attempt。无权/网络失败/合法空数据各有独立UI，错误不能被空数组吞掉。

## 5. AI交互的工程落点

设置Diff使用字段白名单、dirty fields和expectedRevision；未选字段不发送；撤销调用原设置命令且带被撤销修订。数据分析用同一AnalysisResult绘制图表与明细；点击数值携带结果版本/授权查询引用，服务端重新判断。知识引用定位artifact/source版本和段落，前端不拼对象存储URL。

主动卡携带opportunityId/sourceVersion，采用返回draftRef/workRef，不直接创建第二业务实例。P09维护界面通过动作授权展示评估/发布，普通员工只有反馈；真实评估缺失显示待验证。P16的AI缺项提示与人员approve/submit/receive按钮分离，按钮提交仍走原业务命令，不能把模型“通过”作为审批结果。

## 6. 表单、资源与版本

继续复用24号四个示例表单的17字段及底座表单引擎，字段id、类型、精度、单位、校验和读写条件来自同一发布版本。前端可提示必填，后端仍按模板版本校验。岗位权限与流程态共同决定可写字段；隐藏字段也不能在PATCH中写入。日期和金额不经JavaScript浮点重新计算正式结果。

市场列表返回每项独立allowedActions/eligibility；“可见”“可复制”“可用于当前工作”不同。复制成功但连接未配好显示缺项，并携带returnTo返回原配置草稿；返回目标必须是受允许的内部路由。私有提示、记忆和凭据不能随资源复制。升级显示来源版/目标版差异，不覆盖在途绑定。

## 7. 工程检查与交付物

冻结前端commit及lockfile；复用其包管理器和测试方式，不强行升级框架。类型来自冻结OpenAPI/后端DTO的生成或共享契约，禁止仅手写另一份字段含义。引入组件需验证许可、bundle影响和键盘操作；员工工作台优先复用既有组件，不照搬管理表单密度。

验收至少覆盖真实403与过期响应、两实例两角色、保留草稿、上传失败与解析失败、断线重连、鱼骨无发现权节点完全缺席、当前节点定位和大文件预览。单元测转换/守卫，接口测数据合同，浏览器测真实旅程；像素一致性只是UI验收的一层。具体M0—M5见43号。
