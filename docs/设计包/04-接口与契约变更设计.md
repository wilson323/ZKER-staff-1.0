# 接口与契约变更设计

本文件的 A01–A17 是**设计追踪编号，不是 API 路径**。已有 operation 在当前 OpenAPI 中出现，只证明合同存在；挂载、鉴权、持久化及前端消费者需逐条接通验收。新增命令以“候选”标注，未创建或开放任何接口。

## 1. 通用请求、响应与一致性

| 项目 | 合同要求 |
|---|---|
| 身份与租户 | 浏览器 Cookie 会话为唯一 tenant 事实源；不从表单或用户可改请求头决定租户 |
| 请求关联 | requestId、correlationId 沿用现有合同；日志脱敏 |
| 写入前置 | expectedRevision 必须匹配权威对象；执行动作还需当前 Assignment/fencingToken |
| 幂等 | 每个产生业务效果的命令使用 idempotencyKey 与请求摘要；同键异载荷冲突 |
| 返回字段 | object/version、有效业务状态、allowedActions、字段投影和可见的恢复原因；不是前端角色名硬编码 |
| 目录查询 | 当前主体可见集合分页、稳定排序；禁止返回无权对象的名称/总数 |
| 错误 | 未认证、无权/不存在、输入错误、版本冲突、依赖不可用、结果待确认分别映射现有错误信封 |
| 未知结果 | 返回原 request/operation 关联与查证入口，不能建议无条件重试外部写入 |
| 事件 | 聚合内序列、去重和权威回读；客户端先恢复状态再补渲染，不以重连重新发起运行 |

本包不另造公共 error envelope。下文错误大写名称是候选 reasonCode，其 HTTP/Connect 映射要与现有契约一致：通常未认证 401、存在性隐藏使用现有 forbidden_or_not_found、格式错误 400/422、并发冲突 409、真实依赖不可用 503。不能把所有异常统一成 200 + 空数组。

## 2. 全域接口目录

| 编号 | 产品能力与读写边界 | 既有锚点/候选增量 | 最小消费者验收 |
|---|---|---|---|
| A01 | 本人工作台、工作项详情和授权聚合读模型 | 复用现有 business_api 与 WorkItem 页面读面；补齐职责/上下文/贡献投影 | 列表与详情同状态，过滤/刷新/深链接一致 |
| A02 | 领取、分派、释放、转派 | claimWorkItem、activateWorkItem；HumanTask/Assignment 既有命令 | 两人并发仅一人成功，旧责任失效 |
| A03 | Agent 合格候选、配置预览、选择 | previewAgentSelection、createAgentAssignment、supersedeAssignment | 选择来自当前候选；人工路径合法；一项一个有效分配 |
| A04 | 跨人协作请求、接受、拒绝、关联子工作 | 候选 requestCollaboration / acceptCollaboration / cancelCollaboration；复用合法 AD_HOC 创建、HumanTask 和有界 Delegation | 不覆盖父 Assignment；不因邀请取得对方资源权 |
| A05 | 冻结、开始、进度、停止及恢复 | ExecutionSnapshot/Envelope、既有 Gateway dispatch/运行事件；UI 按真实可用操作投影 | DSH 收到真实业务输入；不对 unsupported 显示成功 |
| A06 | 线程、上下文预览/解析、变更与应用证据 | getWorkThread、bindConversationContext；候选 previewExecutionContext / getContextApplication；ContextManifest 版本扩展 | digest 可解析且资料有权可读；装载不是仅文件写入 |
| A07 | 消息、附件、引用、候选产物 | 复用 WorkThreadEntry、Conversation、Artifact 与现有上传/下载能力 | 附件版本可回读，消息去重，引用重新授权 |
| A08 | 提交贡献、接受/退回贡献 | 候选 submitContribution / decideContribution；CompletionCheckResult 复用 | 旧基线/旧成员/旧 Attempt 拒绝，差异可恢复 |
| A09 | 完成检查及正式提交 | evaluateCompletionCheck、submitHandoffPackage、既有 ResultCommit | passed + 当前 revision + 合法审批；事务与幂等成立 |
| A10 | 交接读取、接收和返工 | getHandoffPackage、requestHumanHandoff；接收语义按既有合同补齐 | 必需资料不可读时不能显示可执行 |
| A11 | Agent/技能/知识/记忆/方案生命周期 | createAgentProfile/Version、publishAgentVersion、GeneralSkill 系列、Knowledge ingestion/version 等存量 operation | 草稿→试验→发布→选择→实际执行版本一致 |
| A12 | 工具、连接身份、MCP、外部动作及回执 | registerCapability、enableCapability、invokeCapability、resolveWorkspacePath 等既有 operation | 目录/授权/Grant/健康/执行回执分开，未知效果可查证 |
| A13 | 自动化、消息渠道和通知 | Schedule/ScheduledTask、ChannelBinding/Identity/routeChannelMessage/Delivery 等现有 operation | 真触发、身份映射、去重和停用生效 |
| A14 | SOP 节点配置、预检、版本发布 | SOP Studio/NodeContract 现有编辑命令；增量配置字段与消费者一致 | 画布/表单/发布定义一致，在途快照不被覆盖 |
| A15 | 组织、身份、角色、资源授权与离岗 | 复用既有 IAM 和现有动作注册 | 七类 canonical 登录夹具及对象关系负例通过 |
| A16 | 健康、用量、成本、审计、设置与诊断 | 复用 Runtime/Usage/Audit/Notification 读模型 | 用户只见自身范围；指标有真实分母，恢复可验证 |
| A17 | 员工市场目录、按类型采用及我的复制 | Gallery既有设计与类型动作；详见本文件第7节及市场设计 | 授权列表、三类复制、个人副本、幂等与本人节点选用 |

### 2.1 已核实的 operation 名称

当前 contracts/openapi/staffdeck-public-v1.yaml 可定位到：
claimWorkItem、createAgentAssignment、previewAgentSelection、supersedeAssignment、getWorkThread、evaluateCompletionCheck、submitHandoffPackage、getHandoffPackage、bindConversationContext、createAgentProfile、createAgentVersion、publishAgentVersion、createGeneralSkill、testGeneralSkill、publishGeneralSkill、registerCapability、enableCapability、invokeCapability、startKnowledgeIngestion、buildKnowledgeVersion、createSchedule、createScheduledTask、routeChannelMessage、reconcileChannelDelivery。

这些名称用于复用导航，不是逐一已验证的在线 HTTP。新增命令须先检索同义既有行为；存在等价操作时扩展原命令，不批量添加新路径。

## 3. 关键候选命令明细

| 命令 | 请求字段 | 响应 | 守卫与错误 | 副作用 |
|---|---|---|---|---|
| requestCollaboration | parentWorkItemId、expectedRevision、recipientMembershipId、objective、inputRefs、expectedOutputSchemaRef、dueAt、requiredForParent、delegationRef?、idempotencyKey | requestRef、请求视图状态、可见背景、allowedActions | 当前任务组织协作权；接收者合法；必需贡献必须在合同允许范围；RECIPIENT_UNAVAILABLE / SCOPE_NOT_ALLOWED | 写请求事实与投递事件；不启动对方 Agent |
| acceptCollaboration | requestRef、expectedRevision、idempotencyKey | childWorkExecutionId、childWorkItemId、collaborationLink、当前责任 | 接收人或已有合法分派规则；合法 AD_HOC 输入与 IntentDecision；REQUEST_EXPIRED / ALREADY_RESOLVED | 通过既有创建路径建立子任务、责任和 Link |
| previewExecutionContext | workItemId、candidate/config refs、purpose | 必需/可选引用、有效版本、缺项、裁剪原因、可开始状态 | 只读；按接收者现有权限解析；不生成可用执行票据 | 无 Runtime 运行 |
| 开始执行（既有命令增量） | workItemId、expectedRevision、selection refs、inputResultRef、context preview ref?、idempotencyKey | assignmentId、attemptId、snapshotId、contextBindingId、运行观察入口 | 重新计算资格/上下文；预览不是授权票据；REQUIRED_CONTEXT_MISSING / STALE_REVISION / RESOURCE_UNAVAILABLE | 冻结并派发；保存幂等关联 |
| submitContribution | linkId、childWorkItemId、expectedRevision、attemptId、contextBindingId、basedOnParentRevision、artifactRefs、structuredResultRef、completionCheckResultId、idempotencyKey | contributionId/version、submitted 状态、当前基线或差异 | 当前专业承担人及结果适用性；STALE_CONTEXT / STALE_ASSIGNMENT / CHECK_FAILED | 保存不可变贡献内容与待接受事件 |
| decideContribution | contributionId、expectedRevision、parentExpectedRevision、decision=accept/return、reason、idempotencyKey | 状态、接受记录、主任务完成检查摘要 | 有权汇总者；最新基线；必要职责分离；DECISION_CONFLICT | 保存决定；不直接完成父节点 |
| 正式提交（既有命令增量） | workItemId、expectedRevision、attempt/fence、completionCheckResultId、acceptedContributionRefs、result/evidence/manifest refs、idempotencyKey | commitId、handoffPackageId、业务状态、下游状态 | 所有版本/权限/必需检查/批准仍成立 | 既有 ResultCommit 事务与 Outbox，不跨服务伪造原子性 |
| 接手交接（既有语义补齐） | handoffPackageId/version、targetWorkItemId、expectedRevision、idempotencyKey | 接收事实、必需输入状态、allowedActions | 当前接收责任、精确包摘要、必需引用可读；HANDOFF_INPUT_UNAVAILABLE | 保存接收事实；是否启动仍看执行策略 |

证据上报接口只接受受信 Gateway/控制面服务事实，不能让浏览器提交 state=loaded 就把“数字员工已装载”设为真。客户端可以提交阅读确认，二者属于不同记录。

## 4. 需要先补齐的合同差异

| 差异 | 当前证据 | 设计选择及兼容方式 |
|---|---|---|
| CD-01 ContextManifest 目标 | 当前 schema 必需 targetNodeId，无法自然表达独立 AD_HOC/同节点接收工作 | 候选 v2 使用明确 targetScope 与 targetWorkItemId/targetNodeId 条件分支；保留 v1 节点交接读兼容；正式映射后才能给 AD_HOC 运行生成合法 Manifest |
| CD-02 身份与上下文快照闭包 | 当前 Manifest 不包含 Agent 版本/PluginProfile/业务水位 | 通过 ExecutionContextBinding 引用现有 ExecutionSnapshot 与 Manifest；需插件绑定时补精确 digest，不重复维护 Agent 版本 |
| CD-03 单项一分配 | 数据库 partial unique index 和 current_assignment_id 已约束 | 新增合法工作关联；不删除唯一索引、不复用父 Assignment |
| CD-04 节点配置合同 | 当前 node-contract 主要为职责、模式、输入输出、失败策略；旧扩展提案不等于已应用 | 复用现有提案核对后合并：可选/锁定资源、参数 schema、协作规则、执行/推进策略；不得双写两套节点定义 |
| CD-05 上下文大小与必需资料 | 当前对话滚动最近 8 条、每条摘要 512 字符、16KiB 子预算 | 非交互硬约束单独保留并受支持装载；预算超限需按来源摘要/检索，不偷偷截断必需项 |
| CD-06 消费证据 | 当前 Adapter 明确只保证上下文文件写入，实际读取由 DSH 决定 | 以受支持 DSH 方式绑定并做受控行为验证；loaded 只由合格证据产生 |
| CD-07 policyRevision | 当前纯函数存在字符串比较 | 先确定版本语义；采用可信策略版本关系或既有单调序号，不能以字符串字典序判断业务新旧 |
| CD-08 贡献终态与 ResultCommit | 当前没有证据证明完整父子贡献门已接通 | 扩展提交检查为当前贡献/基线集合；复用原幂等、fence、审批和补偿语义 |
| CD-09 读面与挂载 | getWorkThread 在 OpenAPI 中存在，当前精确引用检索未建立生产消费链证据 | 挂载检查 + 实际 HTTP + 普通角色浏览器；合同声明不能代替路径可用 |
| CD-10 暂停/恢复/运行更新 | 状态合同覆盖比 Adapter 实际动作更广 | capability availability 控制按钮；不支持时使用安全结束/新 Attempt，不另建 Agent Loop |

CD-01 的 v2 目标规则：targetScope=NODE_HANDOFF 时要求 targetNodeId；targetScope=WORK_ITEM 时要求 targetWorkItemId；targetSubjectType 若为 AGENT/HUMAN 则必须解析具体 subjectId 才可开始执行；ROLE/UNRESOLVED 只用于预览，不能派发。新 v2 不能直接发送到当前 v1 解析器；先完成合同版本协商和消费者迁移。

## 5. 示例：候选贡献提交

以下是产品设计示例，ID 为说明值，无在线请求已执行。

~~~json
{
  "linkId": "collab-technical-01",
  "childWorkItemId": "work-technical-01",
  "expectedRevision": 4,
  "attemptId": "attempt-technical-02",
  "contextBindingId": "context-binding-02",
  "basedOnParentRevision": 7,
  "artifactRefs": [
    {
      "ref": "artifact-equipment-list",
      "version": "2",
      "digest": "sha256:aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
      "required": true,
      "purpose": "equipment-configuration"
    }
  ],
  "structuredResultRef": "result-equipment-v2",
  "completionCheckResultId": "check-technical-02",
  "idempotencyKey": "submit-technical-02"
}
~~~

服务端不能信任上述 basedOnParentRevision、digest 或 check ID 的自述，必须加载真实对象校验。若当前父 revision 为 8 且相关设备输入已变，返回版本冲突及本人可见的变更摘要；草稿保留，用户进入“查看变化并重核”。

## 6. 接口测试与联调顺序

先以现有 Schema/OpenAPI 工具定义请求与读模型、补消费者正负例，再实现控制面和 Gateway。新增候选 Schema 只验证字段结构；跨表租户、当前授权、父子关系、状态转换、真实装载、ResultCommit 原子性必须通过真实集成测试证明。

每个 A 编号至少有授权正例、存在性隐藏负例、过期/并发场景、重试/未知结果、刷新回读。通过后补真实浏览器与依赖调用证据；不以生成 TS 类型或单一 HTTP 200 作为接通验收。


## 7. A17 市场目录、按类型采用与个人副本

| 能力 | 输入/输出 | 守卫与恢复 |
|---|---|---|
| list/get market resource | 类型、搜索、当前作用域、分页 → 授权卡片/详情及可见集合统计 | 列表/搜索/详情/缓存/深链接同一投影；无权对象存在性隐藏 |
| preview adoption | sourcePublicationId、sourceVersion、mode、目标个人空间、当前节点 → 复制范围/排除项/依赖/可用性 | 预览不授予复制/调用权；使用点再次判定 |
| adopt by resource kind | 来源版本、COPY_USE/COPY_EDIT/REFERENCE、个人目标、expectedRevision、idempotencyKey → 采用结果 | Agent/Skill/Tool各自领域动作；不同意图/载荷不得混用幂等结果 |
| get/list my copies | operationId/个人作用域 → 副本、Lineage、源/本地版本、readiness、allowedActions | 仅本人获权范围；result_unknown先查证，不盲重试 |
| select in node | 副本资源及版本、workItemId/expectedRevision → 本次配置和候选结果 | published_before_run/Grant/依赖/当前节点资格；不直接启动运行 |
| source upgrade diff | 副本与源新版本 → 可见差异和影响 | 新版本显式合并，不覆盖个人修改及在途快照 |

新增合同差异CD-11：当前泛型copyGalleryResource/addGalleryResource映射到gallery_agent.*，不能用于绕过Skill/Tool策略；先补资源类型分派、独立动作和消费者。市场pure decide只检查Membership/tenant，不能作为完整的资源级过滤或复制授权实现。列入NOT_IMPLEMENTED的操作必须真实接通才可宣称产品可用。

市场读模型见13-市场采用候选.schema.json。allowedActions是UI语义键，必须映射各类型既有授权动作，不新增一套平台权限。原样复制可直接使用的前提是当前发布/采用政策明确允许复用已批准内容且接收方资格齐备，不能把未发布派生稿标为可运行。

## 12. OA聚合与任务隔离接口补充（v2.5）

新增候选接口能力包括统一队列、同口径计数/分页水位、实例发起幂等、按任务保存草稿、审批目标版本和抄送阅读。它们是现有工作台、人员任务、WorkExecution、Approval与通知消费者的增量，尚未冻结为新API端点。准确输入/输出、409/412、来源去重、业务ACL与并发边界见OA补充设计第7节。不得直接把原型数组或浏览器状态升格为后端事实。
