# OA数字员工协作平台开发体系

建立日期：2026-09-11。适用项目标识：`oa-digital-employee-collaboration`。本文件定义当前本地可执行流程，完整Skill为[oa-development-system](../.agents/skills/oa-development-system/SKILL.md)。实际验证范围和结果见[开发体系检查](../validation/development-system-check.json)。

## 当前落地与边界

本项目已有完整设计、需求追踪和本地原型。本轮增加共享Skill、执行入口、任务图校验、证据新鲜度检测、独立进程回归、Claude接续hook和待接入CI文件。复用原设计检查器，不引入第三方工作流平台、Agent运行时或生产服务。

当前没有Git仓库、选定底座、产品源码、部署环境或生产监控。CI配置存在不等于CI执行；hook协议通过不等于每个宿主已自动装载；检查器与Skill也不是权限沙箱。72项真实产品场景保持未执行。

## 一个入口与各自权威记录

| 对象 | 权威位置 | 更新方式 |
|---|---|---|
| 用户意图 | history/用户需求原文.md及后续原文 | 引用原话，助手提案不冒充用户决定 |
| 产品需求/状态 | 30号产品设计追踪数据；27号接口；28号AC；34号EW | 同一需求ID持续记录，不新建并行产品看板 |
| 当前工程任务 | validation/development-workflow.json 的 currentTask | 指向一份 development-task-*.json；历史设计任务保留其原范围 |
| 开发执行规则 | 本文件与项目Skill | AGENTS、CLAUDE、接续提示词均链接同源 |
| 当前本地验证 | validation/development-system-check.json | make verify真实运行后生成，带输入哈希；不是产品就绪证明 |
| 原型/设计证据 | 原validation/文件 | 只按原范围使用；不重复运行历史旧仓脚本 |

`intent → spec → plan → 产物 → 证据 → 后续任务`使用同一任务中的三个字段及文件引用表达，复杂需求可引用专门的Markdown规格。没有必要逐字复制现有设计为三份新文档。简单修订不强制创建任务图。

## 日常执行

```sh
make entry
make verify
make eval
make verify-product
```

`entry`输出实际目录、任务和技术状态；从错误cwd直接运行检查器会失败。`verify`执行当前任务图检查、原设计检查和确定性工具回归，失败返回非零，报告保存命令、目录、退出码、输出和输入哈希。`eval`独立运行工具回归。`verify-product`在缺少底座或任一必要验证层时拒绝运行，不把空检查表判为通过。

新复杂任务用Skill的 `new` 命令创建，任务ID限定为小写字母、数字和连字符；已有未完任务或同名文件不会覆盖。生成的是草稿，必须补全意图来源、范围、验收、节点与恢复方案才允许执行。每个节点只能在前置完成后标记VERIFIED，所有节点必须到达最终验收。保留失败原文及真正采取的修复，不用更新状态掩盖失败。

当前任务是本轮体系改进，不是后续产品任务的永久授权。已有授权内的局部可逆改动直接执行；框架最终选择、范围重大冲突或实际高风险副作用才需要相应决定。默认采用单写者与独立测试进程；确有并行授权时再拆互不冲突任务，并评估返工和集成成本。

## 审查与完成条件

审查标准在[REVIEW.md](../REVIEW.md)。完成前分别核对需求与设计、实现与真实运行、负例与恢复、证据与当前版本。任务状态VERIFIED只表示任务自己声明的范围通过，不抹除其他未完成需求。

软指导放在Skill与项目入口；确定性校验放在Python和Make；生产凭据、网络出站、数据库权限等硬隔离必须由实际宿主/基础设施实现。本轮没有修改这些系统权限，也不以shell命令关键词黑名单冒充不可绕过的沙箱。

Claude的SessionStart只提供上下文，Stop检查最近报告是否与当前文件一致，首次不满足时要求重新验证。若反馈后仍无法通过，则允许报告真实阻塞以避免无限循环，不生成成功凭证。Codex通过AGENTS读取共享Skill并执行Make；不能声称不存在的Codex强制hook。Qoder等工具使用项目接续提示词读取相同入口；未修改外部Waker配置。

记录输入哈希包括本项目文件；排除生成的当前报告、依赖目录、构建输出及秘密配置正文。报告写入采用同目录原子替换，输出符号链接被拒绝。哈希用于检测过期与并发变化，不是签名或第三方证明；具备文件写权限者仍能改动规则，实际合并须由受保护CI/审查制约。

## 底座与产品接入

严格沿28号M0—M5。M0完成前不宣称产品检查已可用。底座选定后在原有开发栈中固定版本、依赖锁与实际许可范围，验证干净构建/同环境OA与AI启动，再将 `product.stackDecision` 指向实际决策文件；`product.status`改为CONFIGURED。

`product.commands`为以下五层分别配置真实的argv数组、超时秒数和证据路径：static、build、integration、business、recovery。优先原框架的命令，不新建重复运行时。命令不是shell字符串，不支持在配置里偷偷拼接其他命令。每层必须在本轮生成新证据；命令非零、超时、文件缺失、复用旧文件、模拟结果均不能通过。

每个产品检查证据JSON至少含：`projectId`、`layer`、`status`、`checks`、`runtimeProvenance`、`simulated=false`；细项必须有实际结果。runtimeProvenance记录代码/构建版本、进程与端口、数据库版本、测试身份范围、工具版本及时间，不包含真实凭据。该结构只验证证据具备必要信息，业务结论仍由实际断言和独立审查支撑。绿色不自动授权发布。

本轮原设计校验器保留严格的“尚未实现”断言。首次提升30号实现/验收状态时，必须在同一任务中把这些断言改成“合法状态+当前代码引用+真实验收证据”校验并补负例；不能直接删除检查或把所有NOT_RUN批量改成PASS。此门禁在M0出口检查，避免历史设计验证器静默放行产品状态。

以M1为首个真实切片：登录→同人两笔业务→本人领取与AI配置→输入版本→真实产物→人员确认→提交→刷新/重启回读。同时执行跨租户/实例、撤权、旧版本、重复和网络错误负例。以后再推进协作/独立审核/正式交付与下游接手。UI至少复核390/1024/1440宽度与真实接口、权限及恢复状态，不能只比截图。

Git和remote获准启用后，复用[CI文件](../.github/workflows/verify.yml)，核验Actions来源并固定实际提交SHA，启用required check与具名审查。当前未提交、推送或触发远程CI。生产发布必须先准备可审查的构建、配置差异、恢复/数据兼容证据和验收结果，再由具名负责人在相应范围授权；不得把“完善开发体系”当作生产批准。

<a id="continuous-evaluation"></a>
## 回归与持续改进

当前回归分两类：`make eval`执行检查器的确定性负例；[Agent行为评测集](../validation/development-agent-evals.json)定义20个情景，状态NOT_RUN。二者不互相替代。本轮实际采用Skill完成本项目工程任务，也不据此推断20个模型情景均通过。

变更模型、提示词、Skill或hook时：固定候选与基线版本、相同输入和工具权限，在隔离目录回放适用案例；记录原始工具动作、产物、耗时、重试及失败原因；产品/权限语义由独立评审核验。新审查Agent先观察，不自动批准。真实事故补入案例；仅在有复用价值且用户授权时更新长期记忆或全局技能。

| 指标 | 真实数据来源 | 如何使用 |
|---|---|---|
| 首次检查通过率、返工次数 | 每个任务首次原始运行和后续修复记录 | 先积累基线；不得只保存最后一次绿灯再计算 |
| 需求到验收耗时、审查等待 | 任务时间与实际审查记录 | 判断瓶颈，不以生成代码行数替代价值 |
| 逃逸缺陷、重复事故、恢复耗时 | 真实事故与回归用例 | 下轮意图引用事故；验证同类问题不复发 |
| 越权尝试、依赖失败、证据过期 | 真实失败记录 | 优先补实际缺口；不为零样本编造仪表盘数值 |

本轮没有生产监控可接入。未来确定性监控观察错误率/延迟等，超阈值才触发诊断；诊断生成同一任务链的新意图。Agent之间的调用也受原授权限制，不能找另一个Agent代为越权发布。没有定时检查的本次要求，因此未创建后台定时任务；持续应用依靠每次工程任务入口与验证。

## 本轮补充验收与共享文件新鲜度

共享Skill文件由 `validation/development-workflow.json` 的 `sharedSkills` 显式列出，`make verify` 对实际文件内容取哈希，发现共享内容改变时不接受旧报告。文件缺失、逃出指定根、内部符号链接、空列表和不支持的类型会失败；该机制不是安全沙箱，也不能防止有写权限者伪造记录。新增参考/脚本需同步清单。

[Python与Node前向试用](../validation/development-portable-forward-results.json)是在两个干净临时目录中由新会话读取Skill完成代码任务，再由主会话运行独立断言，保留原有测试、首次失败与最终结果。产物归档为[试用文件包](../validation/development-portable-forward-artifacts.zip)。每个场景只运行一次，没有基线Skill的同条件对照，不能推断总体模型提升或稳定性。原20项项目行为评测仍保持未逐项运行。

本轮另保留评分器修正：最初对整个测试文件比较哈希，误拒绝了允许的新增测试；现核对原断言保留并独立验证业务结果，未为过关修改实现。此处记录工具判据的错误与修正，不隐去首次失败。

通用Skill目录发生同任务并发写入时，保留并核对双方产物；旧辅助入口改为指向同源实现，未恢复旧正文。最终验证以报告中的真实输入哈希为准，不能保证验证后其他会话不再改动。


本轮独立审查还修复了合法空源码（如`__init__.py`）被证据辅助工具拒绝的问题：输入可以为空但必须匹配哈希，空日志和空交付证据继续拒绝。修复前后记录见[独立审查回归](../validation/development-portable-review-fix.json)。项目来源镜像已同步20项并记录共享规范目录的哈希。
