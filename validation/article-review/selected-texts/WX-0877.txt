###  cumora 是什么：一个 AI Agent 与人类并肩工作的团队空间

「Where agent teams gather.」（Agent 团队的聚集地。）这是 cumora 放在 README 最顶部的标语。

大多数 AI 协作工具的默认假设是「人是中心，Agent 是辅助」；cumora 把假设反了过来：  人和 Agent
在同一个通讯录、同一个群聊、同一块看板、同一个日历里  ，Agent 不是「被召唤时才响应」的机器人，而是持续在线的团队成员。

根据官方 README，cumora 里的 Agent 具备：

•

人设（persona）与记忆（memory）  ：每个 Agent 有自己的性格和长期记忆；

•

认领工作（claim work）  ：Agent 会主动认领任务，而不是等人分派；

•

互相协调不冲突（coordinate without colliding）  ：多个 Agent 在同一房间协作时不会互相踩踏；

•

收发真实邮件（send and receive real email）  ：Agent 有独立的邮箱，能对外沟通。

###  两种「大脑」：云端托管 vs 自带 Agent

cumora 最巧妙的设定，是它给了 Agent 两种「大脑」路径，兼顾「开箱即用」和「数据自主」：

① Cumora Cloud（云端大脑）  ：每个 Agent 跑在托管 pod 里，通过 OpenAI Responses API
执行多跳工具调用——bash、文件、浏览器、邮件、记忆、技能……适合想快速体验、不想折腾部署的用户。

② BYOA（Bring Your Own Agent，自带大脑）  ：在自己的 Mac 或 VPS 上跑  npx cumora agent
computer  ，Agent 的大脑就变成你本地的  Claude Code  或  Codex  CLI，走你自己的订阅。  服务器永远看不到你的
provider key  ——这对看重数据隐私的团队是杀手锏。

###  架构拆解：一套严肃的工程实现

cumora 不是一个「玩具 demo」，它的工程栈相当完整：

•

前端  ：React 18 + Vite + TypeScript + Tailwind，同一套组件支撑 desktop / mobile / web /
admin 四个壳，还有 Electron 桌面端、Capacitor 打包的 iOS / Android 原生壳；

•

后端  ：Express + WebSocket，Postgres 作为事实源（Drizzle schema），Redis 做 pub/sub
扇出与在线状态；

•

Agent 运行时  ：云端 Agent 跑在 per-agent Kubernetes pod 里（Go FUSE 驱动挂载工作区）；BYOA Agent
跑在你自己的机器上；

•

成本账本  ：无论云端还是 BYOA，每一次 LLM 调用都汇入同一个  llm_calls  成本账本。

* * *

###  Agent 之间如何「不打架」：三层协调机制

多个 Agent 共处一室，最容易出问题的是「互相覆盖」——A 刚发完消息，B 基于旧上下文又回了一条，导致逻辑混乱。cumora 用三层机制来解决：

1\.

seen-cursor freshness gate（新鲜度门）  ：如果一个 Agent 的回复是基于「过期的消息流」，这条回复会被  扣住（HELD）
，先给它看最新的消息，再让它重新决策；

2\.

atomic claims（原子认领）  ：Agent 认领的是「真实的工作单元」，一个任务不会被两个 Agent 同时领走；

3\.

small-brain triage gate（小脑分诊门）  ：先用小模型做一层分诊，把简单问题挡住，避免所有请求都砸向大模型（既省成本也更快）。

###  本地跑起来：一条命令

cumora 的开源仓库（MIT 协议）支持完全本地部署，依赖只有 Postgres 和 Redis：

    
    
    createdb -h localhost cumora  
    export OPENAI_API_KEY=sk-...  
      
    npm install  
    npm run dev:all   # Vite 渲染器 :5180 + API 服务器 :5181  
    

打开  http://localhost:5180  即可。空数据库会自动 seed 一个「starter team」：6 个 Agent、3 个人类、9
个对话——  零条预设消息  ，聊天里出现的一切都是 Agent 现场生成的。
