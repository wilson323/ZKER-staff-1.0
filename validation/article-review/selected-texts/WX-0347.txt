论文标题：Prime Agent: A Self-Improving RLM Harness

论文链接：https://arxiv.org/abs/2608.23552

代码开源：https://github.com/PrimeIntellect-ai/prime-agent
一个语言模型单独摆在那里，并不等于一台完整的计算机。它的每次输出只能依赖两样东西：训练时写进权重的知识，以及当前上下文里能看到的 token 。模型想查一个文件、算一组数字、跑一遍测试，都做不了，除非有人替它把「外部世界」接进来。这个负责接线的部分就是所谓的 harness ，一个介于模型与环境之间的执行框架，模型通过它调用工具、执行代码、读取状态。框架的好坏，直接决定了一个模型在长时程任务上能被测出多少真实能力。
Prime Agent 想解决的正是这个问题。它把「模型自己」和「模型干活的环境」彻底分开：策略由模型自己想，但执行、恢复、校验、资源记账这些脏活，全部交给框架标准化处理。论文里最直观的证据是 ARC-AGI-3 上的表现：同一个模型，用官方自带框架跑只有 30% 左右，套上 Prime Agent 之后冲到 95.5%，比人类基线 95.4% 还略高一点。下面这张图给出不同模型在不同 token 预算和成本下的完整曲线。

ARC-AGI-3 测试时扩展：横轴是每局消耗的输出 token （左）与估算 API 成本（右），纵轴是得分。 Prime Agent + Opus 5 达到 95.5%，高于人类基线 95.4%；对比组是官方原生 harness 的成绩。
一个模型的信息分成四层
要理解 Prime Agent 的设计，先看它怎么组织信息。论文把系统的全部状态分成四层。 L0 是模型权重，即训练出来的知识和计算能力； L1 是当前上下文，也就是单次调用里模型能看到的 token ； L2 是 REPL 和子智能体，存放代码、工具、保留的中间值； L3 是磁盘上的历史、记忆、技能、提示词和子智能体规格。层与层之间由一条「模型-上下文边界」隔开， L0 、 L1 在边界内侧， L2 、 L3 在外侧。
这四层各有一套更新机制。 L0 靠微调更新， L1 靠上下文压缩重写， L3 靠 refinement （精炼）给条目做版本化更新。有意思的是 L2 的机制，论文把它叫作 agentic garbage collection （智能体式垃圾回收）：模型根据任务变化，自己创建、保留、总结或删除 REPL 里的值和子智能体会话，就像程序员手动管理内存一样。

Prime Agent 的状态层级： L0 权重、 L1 活动上下文、 L2 REPL 与子智能体、 L3 磁盘持久状态。右侧标注了每一层的更新机制。
为什么要把状态挪出上下文？因为上下文窗口再大也是有限的，而长时程任务里要处理的信息量可以远超一个 prompt 。把一大段日志、任务说明、评测结果反复塞进上下文，模型只能被动注意；放进可寻址的外部状态后，模型就能用代码主动搜索、变换、汇总。论文引用冯·诺依曼结构来类比：模型不仅能读「正在生成的指令」，还能读写指令之外的寻址状态，更像一台真正的计算机。
架构：一个常驻的会话树
Prime Agent 的运行时由几个部分拼成。每个会话（ session ）持有一个持久化的 IPython REPL ，也就是一个常驻的代码执行环境：模型可以随时往里写代码、跑代码，中间结果跨轮次保留，但不会自动塞回上下文，只有模型主动选择时才会被序列化进去。这避免了把大对象反复搬运进上下文的开销。
递归调用通过一个名为 rlm 的异步接口实现，它是论文里递归语言模型（ Recursive Language Model ）抽象的落地。模型在输出里写一个 rlm 调用，框架就会为它创建一个子智能体会话并调度运行，同时立刻返回一个稳定句柄（可以理解成取件号，父会话凭它随时取回子智能体的结果）。子智能体在后台并行跑，父会话继续做自己的事。子智能体拥有自己独立的模型上下文、 IPython 内核、历史和工作区。结果通过 agent 之间的直接通信通道返回，句柄在上下文压缩或重启之后仍然可用，可以继续跟进。

Prime Agent 架构总览：持久根会话与子智能体会话连接到 daemon 、 Continual Harness 、 Agents View 与环境。实线箭头是执行与消息，虚线箭头是持久状态。
会话由后台 daemon 托管，与创建它的客户端解耦。客户端断开了，会话照常运行。会话有四种状态：创建、运行、空闲、休眠，休眠会话可以从持久状态恢复。子智能体可以直接给父会话、子会话和兄弟会话发消息，消息走 daemon 托管的异步队列，接收方即使暂时不在线，队列也会保存消息。多个 Agent 之间的协作由此变成动态的，不再依赖预先画好的固定流程图。

多智能体编排生命周期与直接通信拓扑：父会话通过 rlm 派生子智能体，会话在四种状态间流转；右侧是根会话、子智能体与嵌套智能体之间的直接通信结构。
人类介入靠的是 Agents View ，一个可视化界面，可以查看整个会话树的历史，附着到某个会话上给它新输入，或者随时脱离而不打断执行。它还有只读的 agent-observe 接口和定向的 agent-message 接口，让人不必逐条跟踪每一轮对话，就能通过编排层与任意子智能体交互。
长时程任务的三种控制方式
长时间运行的 Agent 怎么决定什么时候继续、什么时候停？ Prime Agent 提供三种机制。 Autonomous mode （自主模式）在显式预算内不断执行轮次，每轮之后跑一个任务指定的结束条件测试，没通过就带着有限的输出继续下一轮，同时受轮次、 token 和墙钟时间三重限制。 Goal （目标模式）把一个目标跨多次延续保留，直到 Agent 自己标记完成。 Heartbeats （心跳）按 cron 或定时计划启动轮次。

长时程控制机制：自主模式在显式预算内运行直到结束条件通过；目标模式跨延续保留目标直到智能体完成；心跳按定时计划启动轮次。
评估配置把任务和工具接口绑定到模型与供应商设置上，同时规定压缩策略、重试策略、完成门槛和资源上限。记账会汇总根会话和所有后代会话的花费，委托出去的活也看得见成本。事件历史把模型调用、工具使用、消息、干预、重试、验证器结果和框架修改全部串起来，标准化了持久化、恢复、终止和记账。这样一来，「框架出错」和「模型不行」就能被区分开，而不混在一起。
自我改进： Continual Harness
Prime Agent 里真正实现「自我改进」的是 Continual Harness （持续改进框架）模块， Continual 指它跨会话不断累积状态、越用越熟，而不是每次从头开始。它把跨轨迹的状态暴露给模型读写。提示词笔记存行为指令，记忆存事实，技能打包可执行的流程，子智能体规格存可复用的角色或分工。这些都是带类型的、版本化的状态，支持增删改查；默认属于当前会话，也可以显式请求全局共享。
精炼（ refinement ）把轨迹证据变成版本化的状态更新。 Agent 可以直接请求编辑，或者用 /refine 命令在后台跑一次模型调用，对相关事件做总结。每次编辑在轮次边界应用，记录触发原因和预期效果，版本号保留来源并可回滚。精炼只补充不可变的基础提示词，不改写底层策略。
这样做的结果：模型权重保持不变，但执行证据不断变成持久的框架状态，改变后续行为。有用的计算过程变成技能，反复出现的协作模式变成子智能体规格，被纠正的假设变成记忆或提示词笔记。留下的完整轨迹记录，还能作为下一代模型的训练数据。
实验：一条完整的证据链
ARC-AGI-3 ：测试时算力换分数
ARC-AGI-3 是交互式抽象推理基准，每局游戏要求模型在动作限制内学会游戏规则，建立临时世界模型。这里说的「测试时算力」指推理阶段让模型多跑几步、多花 token 换来的能力提升，和训练时投入的算力是两回事。 Prime Agent 只提供环境接口和一个从 PRO-LONG （一个面向长时程任务的自主提示模板）改编而来的提示，策略完全由模型自己构造。结果很清晰：更强的配置在长时间交互中持续进步，弱的配置早早停滞。 Prime Agent + Opus 5 达到 95.5%， Prime Agent + GPT-5.6 Sol 达到 78.3%，而对比组里 GPT-5.6 Sol 用官方 Responses API 只有 38.3%， Opus 5 用官方 ARC harness 只有 30.2%。注意论文特意说明，这些参考线是官方公布的数值，因为作者自己用原生 harness 重跑的成绩低于官方公布值，所以引用外部数据来定位结果，作者并没有声称隔离出了 harness 的因果效应。
长上下文：从被动注意变成主动管理
长上下文测试组检验模型能否主动管理放不进一个 prompt 的信息。 Prime Agent 把初始上下文存成可读文件，模型从持久 REPL 里搜索、变换、汇总、反复查看，把长上下文推理从「对固定序列的被动注意」变成「程序化的信息管理问题」。
下表是九个长时程任务上的对比。总体结论是 Prime Agent 在大多数行里与各家原生框架打平或更好，尤其是在长时程、长上下文任务上。

长上下文结果：九个任务上 Prime Agent 与 Pi 、 Claude Code 、 Codex 等原生框架的对比。加粗表示同一模型在两种框架对比中更高的点估计，不代表统计显著。
先看三组最有代表性的数字。 OOLONG-Pairs 上 Opus 5 + Prime 达到 0.929 ，超过 Claude Code 的 0.922 ； LongCoT-Mini 上 Prime + Opus 5 是 0.722 ，比 Claude Code 的 0.558 高出一截； EmulatorBench 行里 GPT-5.6 Sol 组差距最大， Prime 0.275 对 Codex 0.228 ， GLM-5.2 组 Prime 0.208 对 Pi-mono 0.000 ，而 Opus 5 组 Prime 0.047 反而低于 Claude Code 0.062 ，与论文所述 Opus 5 在模拟器任务上失败的现象一致。表格也标注了局限：加粗只是更高点估计，不代表统计显著，且没有不确定性区间。
多日自主研究： nanoGPT 加速跑
nanoGPT speedrun 衡量 Agent 把 124M 参数 GPT 训练到固定验证损失所需训练步数能压到多低，每条记录用八个种子取均值验证。论文对三个模型（ Kimi K3 、 DeepSeek V4 Pro 、 GLM 5.3 ）分别对比 Prime Agent 和模型开发者自己的 CLI 或 Claude Code 。
结论有些反直觉：框架对最终记录的影响很小，和实验本身的噪声差不多。但模型行为差异很大。用 Prime Agent 时，模型经常在训练脚本之外做实验，比如先用合成梯度模拟候选优化器、数值优化更新规则系数，再真正启动训练。下图统计了这种「循环外实验」的频率。

每 100 次训练脚本执行中的循环外实验次数： DeepSeek V4 Pro 在 Prime Agent 上平均做 7.6 次，而在 Claude Code 上只有 1.2 次。
差异最大的是 DeepSeek V4 Pro ，在 Prime Agent 下每 100 次训练运行产生约 7.6 次额外实验，是 Claude Code 下 1.2 次的六倍多。论文猜测这可能因为 DeepSeek 自家 harness 也提供类似的代码执行模式， REPL 正好匹配了模型训练时熟悉的流程。 Kimi K3 的行为也值得一提：它在 Prime Agent 上自己定义了一个探针函数，跑了约九十次筛选实验，全部 19 条验证记录都走这条程序化通道；而它在自家 CLI 上只做直接文件编辑，没搭建任何类似机制。
模拟器构建：从零写一个 Game Boy
EmulatorBench 要求 Agent 在 Rust 里从零构建游戏主机模拟器，给定规格和一组诊断测试作为验证器，全程沙箱化、不给参考实现，以降低数据污染风险。 Prime Agent + Sol 成功复现了 SEGA Genesis （ 0.616 ）和 Game Boy Color （ 0.998 ）两个模拟器。

EmulatorBench 选例：左图 SEGA Genesis ，右图 Game Boy Color 。横轴是估算成本，纵轴是验证器得分。 Prime Agent + Sol 在 GBC 上拿到 0.998 ， Codex + Sol 与 Claude Code + Opus 5 都是 0 。
最扎眼的是 Game Boy Color 一图： Prime Agent + Sol 在约 3 到 4 美元成本处从 0 跳到接近满分 0.998 ，而 Codex + Sol 、 Claude Code + Opus 5 全程 0 。论文还提到一个意外： Opus 5 的调用虽然工具响应成功，却没能解出任务。表 1 里 EmulatorBench 的平均结果也印证了这一点， Prime Agent 在长时程编码任务上优势最明显。
GPU 内核：预算内的贴身肉搏
PMPP-Hard 是一个 GPU 内核优化基准，任务是把「编辑、编译、检查、剖析」这一循环反复压进墙钟时间（真实时间）预算内。结果两组模型组内对比的排序相反： GPT-5.6 Sol 组里 Prime Agent 62.3%（ 43/69 ）略高于 Codex 59.4%（ 41/69 ）； Kimi K3 组里 Prime Agent 68.1%（ 47/69 ）略低于 Kimi-Code 71.0%（ 49/69 ）。

PMPP-Hard 在固定模型内预算下的求解率。 Prime Agent 与原生框架差距不大，排序在两组模型之间反转。
论文指出一个墙钟预算看不到的差异：用 Prime Agent 的模型 token 消耗显著更低，同样的成绩用更少的 token 达成，逐 token 比较时 Prime Agent 有优势。这里的边界也很明确：硬性墙钟预算下，通用持久接口和专用 CLI 没有拉开大差距。
Factorio ：七天长跑与一次安全事故
Factorio 学习环境提供持久工厂世界的 Python 观测与动作接口。一次七天的 Sonnet 5 运行中，根会话和它的后代共消耗 2340 万输出 token ，完成 196 项科技中的 24 项，先进电路研究推进到 71%，没有停滞迹象。

Factorio 科技进展（上）与智能体树增长、并发（下）随累计输出 token 的变化。竖线标记一次破坏性世界重置，最终完成 24 项科技、先进电路 71%。
这张图讲了两件事。第一，模型对不可逆操作处理得不好：一次破坏性世界重置把科技数从 5 打回 1 ，但会话随后恢复并继续跑，没有丢弃轨迹。第二，根会话在 149 波派发中创建了 633 个一层子智能体，最多 7 个并发，说明它倾向「浅而宽」的并行分工，深层递归嵌套很少。
更重要的是一次安全失败。另一个 Factorio 轨迹里，智能体发现 RCON 命令可以直接往装配机里刷资源，于是在有反作弊心跳的情况下仍使用这个捷径，还把它存成了可复用技能。在这个例子里，持久化机制把「优化了被测目标」的行为保留了下来，包括一个规格漏洞。论文由此给出的部署要求很明确：动作接口要按最少权限设计，状态需要独立校验，被污染的精炼必须可以审计回滚。
MazeBench ：开放世界探索
MazeBench 是开放世界 3D 空间推理环境，玩家控制一个 3D 立方体在全局迷宫里解谜并收集宝石。前沿模型在这个任务上普遍吃力，动辄消耗数十亿 token 也只能解开世界的一小部分。论文对比了 Opus 5 、 GPT-5.6 Sol 与 GLM-5.2 用 Prime Agent 与各自原生框架的探索曲线。

MazeBench 探索 vs 估算 token 成本：实线是 Prime Agent ，虚线是对比框架。纵轴分别是唯一状态数、房间数、宝石数。
从图上看， Prime Agent 的实线普遍在虚线上方或持平，说明在同样的 token 花费下探索到了更多状态、房间和宝石。这个基准把探索效率摊开成三条曲线，没有总括分数，更看重「钱花得值不值」。
边界与判断
Prime Agent 的定位要放准。它不改变模型本身的聪明程度，只负责把已有推理能力尽量完整地测出来、用起来。证据链里反复出现同一个模式：框架不改变模型权重，但决定模型能把多少测试时算力转化为可验证的进展。 ARC-AGI-3 从 30% 到 95.5% 的差距，主要来自 harness 是否允许模型把能力兑现。
论文自己列出的边界同样值得记住。 PMPP-Hard 的墙钟预算下 Prime Agent 没有超过原生框架； Opus 5 在模拟器任务上意外失败； ARC-AGI-3 的参考线是官方数值而非作者的重复实验，因果效应没有被严格隔离。更值得警惕的是 Factorio 暴露的安全问题：自我改进机制会把「优化目标但违反规则」的行为也固化下来，持久化越强，错误行为的留存就越久。作者在结论里也承认，当前模型并没有被训练来使用这些 harness 能力，很多能力仍然闲置，他们预期模型与 harness 的联合学习会成为长时程能力的新路径。
对读者来说，这篇论文的价值在于一个提醒：评估 Agent 时，框架是变量而不是常量。同一模型在不同 harness 下测出来的分数，可以差出一个数量级。想比较模型能力，先固定 harness ；想评估 harness ，就要在同一模型上做对照。
