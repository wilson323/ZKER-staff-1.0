# OA 开发体系执行

先应用通用 `ai-native-sdlc`（当前标准位置 `~/.agents/skills/ai-native-sdlc/SKILL.md`），本文件只增加OA项目身份、需求和命令映射。通用Skill不可替代本项目权威记录。已采用的共享文件在 `validation/development-workflow.json` 的 `sharedSkills` 显式列出，`make verify` 将其纳入证据新鲜度；新增参考或脚本时同步该清单。

本Skill是通用 `ai-native-sdlc` 的OA业务适配。跨项目方法由通用Skill负责；本文件只在项目标识匹配时使用。不要把此适配推广到其他项目。

所有相对业务路径均以项目根为准；Skill目录是 `.agents/skills/oa-development-system/`。先解析实际 cwd 和 `validation/development-workflow.json`：只有 `projectId=oa-digital-employee-collaboration` 才使用本项目命令。缺少标识时只解释适用边界，不自动初始化、复制资料或搜索相邻旧仓。

## 入口与上下文

运行 `make entry`。读取 AGENTS.md、README.md、CONTEXT.md、history/用户需求原文.md及当前任务涉及的后续原文。随后按需求ID精确读取30号追踪、27号契约、28号AC与34号EW；不要默认重读全部历史。语义关系不明时优先可用的 zvec 搜索，索引缺失后用 rg；不自动建立索引。

明确区分：153项原需求、12项AI增量、8项工作台细化、72项场景；原型、文档、真实产品各自留证。人员配置数字员工、OA多流程多实例、执行/协作/审核、私有上下文、市场权限与交付版本是贯穿约束。底座研究推荐不是已批准架构。

## 选择任务路径

- 单文件、低风险、可逆任务：读取—编辑—针对性检查—`make verify`；不强制生成任务图、审批或报告。
- 多文件、跨模块、失败恢复任务：复用配置中 `currentTask`。同一目标继续更新原记录；新目标用下面命令创建草稿，补齐后才执行。只读探索可先进行，不需要为已授权的局部变更重复确认。
- 产品实施：先读 [底座与产品接入](../../../docs/开发体系.md#product-adoption)，沿28号 M0—M5；未选底座仍可准备比较或映射，不自行决定安装/迁移。
- 故障/模型/提示词/Skill变更：按 [回归与持续改进](../../../docs/开发体系.md#continuous-evaluation) 选择真实失败样本，先捕获失败，再最小修复和同条件复核。

```sh
python3 validation/development_workflow.py new --id task-id --goal '本次用户目标'
```

新任务使用 [task-template.json](assets/task-template.json)。它将 intent/spec/plan 放在同一记录内并引用现有文档，避免重复抄写三份规格。规划、需求或接口已有权威文件时直接引用。

## 执行与验收

1. 在任务记录锁定意图来源、交付物、验收、允许文件/排除项、需求ID、代码版本或文件哈希。不得把旧任务批准扩大到新操作。
2. 填写节点前置、操作、工具、输出、成功条件、失败与恢复；所有路径通往最终验收。先跑 `make verify` 校验任务图。根据真实结果更新节点状态，不能直接把计划列为完成。
3. 使用已存在的框架、身份、流程权威状态和执行循环。每次只推进有依赖证据的小切片。没有明确并行授权时用顺序执行和独立测试进程复核；获准后只拆真正可独立的任务，写范围不重叠，集成由主执行者负责。
4. 修改前给出复现/当前基线；修改后检查来源、差异、语法/静态、相关测试与构建。针对权限、幂等、并发、过期版本、取消/恢复选取负例。每次失败仅在有新诊断时重试，默认最多两次。
5. 按 [REVIEW.md](../../../REVIEW.md) 检查原始产物。以独立进程、不同规则或获准的独立审查会话减小自证盲区；不能虚构审查者或人工批准。
6. 运行 `make verify`。有产品改动再运行 `make verify-product`，并完成适用需求与场景的真实验收。保存命令/退出码/范围/输入哈希/日志，源码改动后重跑受影响检查。旧报告不能充当当前通过证据。
7. 更新同一任务的完成节点、产物、证据、review与限制；最终运行 `make verify` 封存当前状态。交付结果、文件链接、检查结果和未验证边界。

本轮已配置的本地检查不会提交、安装、部署或写生产；以后添加产品命令时必须先审查其实际副作用。外部发送、敏感配置、不可逆操作按当前授权边界处理。传给子Agent/连接器的任务也只能使用原主体权限，不能通过其他执行者扩大权限。

## 持续使用与演进

默认工程入口每次都读取本Skill。Claude入口、Codex入口与Make共用同一个检查器和任务指针。当前会话未动态刷新技能菜单时，直接读本文件继续执行，不声称宿主自动加载已验证。

`make eval` 是确定性工具回归。`validation/development-agent-evals.json` 是行为评测场景；未真实运行模型回放时保持 NOT_RUN。完整步骤与启用边界见 [开发体系](../../../docs/开发体系.md)。不得把结构检查、一次成功或文案变化当成模型能力提升；也不得自动写长期记忆、扩大权限或更新全局Skill。
